# Psycho

Рабочий репозиторий команды кейс-чемпионата «Клинический компас 2026».

Здесь находятся рекламный лендинг концепции **«Синкли»**, рабочее место врача с ASP.NET Core 10 и PostgreSQL, административный веб, мобильный прототип пациента, стенды компонентов и материалы команды. Основание требований — [официальный кейс](docs/official/2026-10-15-case.md). Проверки и учебный режим используют синтетические данные. Лендинг остаётся необязательным демонстрационным референсом.

В рабочем месте врача доступны карта пациента, эпизоды, создание и проведение приёма, план и направления, динамика, дневник, события, сообщения и документы. Подготовлены все 18 локальных форм шкал для последующего выбора версии врачом; автоматические клинические правила ещё не утверждены. [Запуск и хранение данных](docs/doctor-workspace-runbook.md), [спецификация и 38 источников](docs/specifications/doctor-web/2026-10-22-doctor-web-specification.md), [фактическое покрытие и проверки](docs/verification/doctor-workspace.md).

22 октября добавлен [мобильный прототип пациента](apps/mobile-patient/README.md) на React Native + Expo: онбординг, два анимированных маскота, три темы, план, самоотчёты, история и демонстрационный чат. Это локальный интерфейс на синтетических данных; настоящий мобильный клинический сценарий с сервером пока не реализован. Проверка: `npm run check:mobile`; запуск: `npm run dev:mobile`.

**Прямой push в `main` запрещён. Все изменения — через отдельную ветку и pull request с проверками и независимым одобрением.** [Правила команды](CONTRIBUTING.md), [инструкции ИИ-агентам](AGENTS.md), [план пяти участников](docs/superpowers/plans/2026-10-19-five-contributor-development.md).

## Посмотреть лендинг

```sh
npm ci --ignore-scripts
npm run dev -- --port 8765
```

Открой адрес, напечатанный Vite. На первом экране есть входы «Демо врача» и «Демо администратора»; каждое приложение открывается на том же адресе и содержит ссылку «На сайт Синкли». Старый учебный сценарий доступен отдельной кнопкой. [Инструкции и демонстрационные сценарии](site/README.md).

`npm run build` создаёт единый статический сайт в `dist/`: лендинг и приложения в `demo/doctor/` и `demo/admin/`. Для публикации нужен весь `dist/`, включая общие ресурсы `assets/`. Для локального просмотра сборки: `npm run preview -- --port 8766`. Шрифты и графика локальные; демонстрационные данные вымышлены.

## Веб-приложения и примеры компонентов

После установки зависимостей из корня:

```sh
npm run dev:doctor
npm run dev:admin
```

Каждую команду запускать в отдельном терминале. Веб врача: [127.0.0.1:8767](http://127.0.0.1:8767/); административный веб: [127.0.0.1:8768](http://127.0.0.1:8768/). `npm run dev:examples` запускает оба сервера и печатает прямые ссылки на разделы `#/examples`; Ctrl+C завершает оба процесса. Серверы доступны только локально. Занятый порт даёт ошибку; для отдельного приложения можно указать другой: `npm run dev:doctor -- --port 8770`.

Веб врача по умолчанию открывает вход в клинику или учебное рабочее место с шестью синтетическими пациентами и сохранением в IndexedDB. Прежнее демо врача с восемью пациентами и вариантами данных доступно по `#/legacy`. В админке одна учётная запись переключается между тремя рабочими пространствами: координатор выполняет организационные задачи, руководитель просматривает сводку и отчёт, системный администратор управляет учебными ролями и журналом. [Состав исходных демонстрационных данных](docs/verification/2026-10-20-demo-style-data.md), [сценарии трёх пространств администратора](docs/verification/2026-10-20-admin-workspaces.md).

Компоненты задач #5–#7 представлены заготовками в отдельном разделе «Примеры». Общие кнопка, поле, базовый диалог и график работают в стенде. Смена набора данных или примера сбрасывает локальное состояние и журнал callbacks. Эти изолированные примеры не сохраняют данные и не обращаются к API. [Точные файлы, контракты и примеры для участников](docs/team/web-components.md).

Структура: `apps/web-doctor`, `apps/web-admin`, `packages/ui-web` — npm workspaces с одним корневым lockfile. Общий пакет импортируется из исходников без предварительной сборки. Отдельные сборки приложений лежат в их собственных `dist/`; корневой `dist/` содержит сайт с обоими демо. Входы в `site/demo/` подключают существующие приложения, не копируя их реализацию.

Концепция экосистемы, дополнительные функции и целевая архитектура описаны в [продуктовом документе](docs/ideas/2026-10-15-syncli.md). [Матрица покрытия ТЗ](docs/official/2026-10-15-coverage.md) отличает представленные возможности от функций и испытаний будущего клинического продукта.

## Начало работы

Нужны Git и Node.js **24.x** с npm. Версия Node.js для локальной работы и CI указана в [.node-version](.node-version).

[Подготовка каждого из пяти участников](docs/team/local-development-setup.md): что установить, как проверить рабочее место и какие инструменты нужны только главе разработки. Участникам 2–5 не требуется устанавливать серверный или мобильный стек.

[Стартовые GitHub Issues и порядок работы](docs/team/backlog.md): задачи, зависимости, назначение ролей и правила статусов. Оперативный трекинг ведётся в GitHub Issues.

Из корня репозитория:

```sh
npm ci --ignore-scripts
npm run check
```

Общая команда проверяет документацию, синтаксис лендинга и сборку сайта с демо. Дополнительно выполните `npm run check:web` для типов, поведенческих проверок и самостоятельных сборок веб-каркасов и `npm run check:fixtures` для схемы и синтетических наборов. Все три команды требуют только Node.js 24/npm. [Принятый стек](docs/decisions/0002-product-stack-and-delivery.md) также предусматривает React Native/Expo, ASP.NET Core 10, PostgreSQL и REST/OpenAPI; серверные и мобильные команды появятся с соответствующими приложениями.

## Команды

| Команда                  | Назначение                                                      |
| ------------------------ | --------------------------------------------------------------- |
| `npm run check`          | Общие проверки и сборка сайта с демо                            |
| `npm run check:web`      | Типы, поведенческие проверки, сборки двух веб-приложений        |
| `npm run check:fixtures` | Проверки схем, наборов примеров и данных обоих демо             |
| `npm run format:check`   | Проверить форматирование поддерживаемых текстовых файлов        |
| `npm run format`         | Исправить форматирование                                        |
| `npm run docs:check`     | Проверить локальные Markdown-ссылки, якоря и определения ссылок |

Проверка документации работает офлайн. Доступность внешних сайтов и достоверность медицинских источников она не оценивает. Исходное ТЗ сохраняется в авторском оформлении: форматтер его пропускает, а ссылки в нём проверяются.

## Автоматические проверки

[Workflow Repository checks](.github/workflows/checks.yml) содержит отдельные Repository checks, Web checks и Fixture checks на Ubuntu и Windows для PR в `main`, push в `main` и ручного запуска. Они выполняют соответственно `check`, `check:web` и `check:fixtures`. Новый запуск для того же PR заменяет устаревший.

GitHub Actions включены; 19 октября 2026 года [проверки main на Ubuntu и Windows прошли](https://github.com/souponin-d/psycho/actions/runs/38772196396). Для каждого нового PR нужны результаты его собственного запуска. Обязательность проверок и ограничения на слияние задаются отдельно в настройках репозитория; текущий блокер защиты приватного репозитория описан в [CONTRIBUTING.md](CONTRIBUTING.md#настройка-github).

Веб-проверки подтверждают работу каркаса и общих примитивов. Они не доказывают готовность клинических сценариев, доступа, сервера или мобильного приложения. [Проект P01a](docs/superpowers/specs/2026-10-19-web-foundation-design.md), [план реализации](docs/superpowers/plans/2026-10-19-web-foundation.md).
