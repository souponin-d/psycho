# Тестовый доступ для хакатона

26 октября 2026 года. Уточнение владельца заменяет предложение о регистрации пациента с логином/паролем. Первый результат — реальная связь Android с сервером и кабинетом врача на синтетическом пациенте. Медицинский production-профиль остаётся следующим отдельным этапом.

## Вход в Android

- При каждом новом запуске приложения показывается один экран: «Код доступа», поле кода и кнопка «Войти». Регистрации, почты и пароля пациента нет.
- Один выданный код допускает повторные входы и связан на сервере с одной синтетической картой. Он не погашается после первого использования; отключение/срок задаётся на сервере для хакатона.
- Код проверяет API по HTTPS. Успех открывает сессию только роли patient с серверной привязкой к карте; клиентский ID не выдаёт доступ.
- При неверном/отключённом коде и ошибке соединения остаётся экран входа с понятной ошибкой. Локального обхода через учебный режим нет. Существующие история и игровой мир при входе не сбрасываются.
- Код и пароль врача не вшиваются в APK/web-сборку, не записываются в URL/логи. На сервере хранятся стойкие хэши, действуют ограничения попыток. Общий код предназначен только для этого синтетического сценария.

## Вход в кабинет врача

- Используется форма логина и пароля и обычная серверная сессия роли doctor.
- Кнопка «Открыть учебное рабочее место» не является способом входа в хакатонном релизе; учётные данные вводятся в форму.
- Врач получает доступ к той же синтетической карте. Код Android не открывает врачебные полномочия.

## Минимальный сквозной результат

Пациент вводит код → сервер подтверждает сессию → пациент отправляет тестовое сообщение → оно сохраняется в PostgreSQL и видно врачу в серверном веб-кабинете → врач отвечает → приложение получает ответ. Проверяется два повторных открытия приложения с тем же кодом, неверный код, неверный пароль и недоступность сервера. HTTP/ошибка сети не считаются успешным входом или доставкой.

Первая защита прототипа: HTTPS с проверкой сертификата, серверные роли/проверки доступа, хэши секретов, ограниченные сессии и попытки входа. Реальные медицинские данные не подключаются этим этапом. Утверждённые темы/маскоты/экраны сохраняются; новый экран доступа сначала предъявляется владельцу до внедрения согласно прежнему требованию.

Развёртывание зависит от доступного VPS и домена для сертификата. Обновление планов, опросники и полная офлайн-синхронизация не блокируют этот первый результат.
