## Как вести работу

1. Перед новой задачей сверить состояние issue, зависимостей и актуальный `origin/main`. CustDev проводится отдельно; интервью не заменяют репозиторные задачи участников.
2. Использовать существующие приложения и [стенды H-компонентов](web-components.md), где перечислены файлы, импорты и URL. До принятия зависимости в main и обновления GitHub Issues зависимая задача остаётся заблокированной; само наличие кода не меняет статус.
3. После проверки зависимостей снять `status:blocked`, назначить реального исполнителя и поставить `status:ready`. Одна активная задача на участника; следующая выдаётся после принятия предыдущего PR.
4. Для открытой issue использовать одну текущую метку: `status:ready` → `status:in-progress` → `status:in-review`. При новом блокере поставить `status:blocked` и описать его. Зависимость или создание issue сами по себе метки не переключают.
5. PR связывается с задачей через `Closes #номер`. Закрытие после принятого PR означает выполнение; отменённую задачу закрывать с причиной и `not planned`. Для закрытой задачи статус задаёт состояние issue, оставшуюся статусную метку следует снять.

Отдельная доска Projects для начала не нужна: [все открытые задачи](https://github.com/souponin-d/psycho/issues), [готовые к работе](https://github.com/souponin-d/psycho/issues?q=is%3Aissue%20is%3Aopen%20label%3Astatus%3Aready), [заблокированные](https://github.com/souponin-d/psycho/issues?q=is%3Aissue%20is%3Aopen%20label%3Astatus%3Ablocked). Assignee и метки обновляются в GitHub, а не дублируются как оперативные статусы в Markdown.
