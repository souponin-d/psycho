# Веб-каркас: входы для участников 2–5

Дата сверки: 29 октября 2026 года. Основание первоначального каркаса — [задача #4](https://github.com/souponin-d/psycho/issues/4). Ниже сохранены контракты первых H-задач и входы действующего стенда; это не перечень текущих незакрытых задач. Актуальные назначения и зависимости проверяются в GitHub. Новая ветка создаётся от актуального origin/main после принятия зависимости через PR; наличие файлов в незавершённом PR не снимает блокировку.

## Установка и запуск

Из корня клона с Node.js 24/npm:

```sh
npm ci --ignore-scripts
npm run check
npm run check:web
npm run check:fixtures
npm run dev:examples
```

Последняя команда запускает оба приложения. Открыть [примеры врача](http://127.0.0.1:8767/#/examples) или [примеры администратора](http://127.0.0.1:8768/#/examples). Ctrl+C останавливает оба сервера; повторный запуск не требует ручного завершения дочерних процессов. Занятый порт — ошибка, а не автоматический переход на неизвестный адрес.

Для одного приложения доступны dev:doctor и dev:admin. Другой порт задаётся аргументом, например `npm run dev:doctor -- --port 8770`. Никакие .NET, Docker, API и мобильные SDK для этих команд не нужны.

Для просмотра с лендинга можно выполнить `npm run dev -- --port 8765` и открыть сайт: «Войти врачу» ведёт в рабочее место по `doctor/`, а «Демо администратора» — в `demo/admin/` на том же порту. В `site/doctor/` и `site/demo/admin/` находятся только точки подключения; компоненты продолжаем редактировать в разрешённых файлах ниже. `npm run build` собирает сайт и оба входа в корневой `dist/`; самостоятельные команды приложений сохранены.

## #5: список пациентов

Импорт: `import type { PatientListViewProps } from "@psycho/ui-web/contracts"`. Экспорт компонента: `PatientListView`.

Вход rows — массив `{ id: string, displayName: string, secondaryText: string }`. Порядок сохраняется. При действии пользователя вызвать `onSelect(id)` один раз; HTTP и расчётов не добавлять. Стенд покажет id в области выбранного пациента и аргумент в журнале.

Открыть «Список пациентов · #5», переключить «Обычные», «Пустые», «Длинные подписи», проверить клавиатурный выбор и callback. В обычном наборе две вымышленные записи; в empty записей нет. Смена набора очищает выбор и журнал. В PR приложить три состояния и результаты check/check:web.

## #6: сводка отделения

Импорт типа: `DepartmentSummaryViewProps` из `@psycho/ui-web/contracts`; примитив графика: `LineChart` из `@psycho/ui-web`. Экспорт компонента: `DepartmentSummaryView`.

items содержит `{ id, label, value: string | null, caption?: string }`. Строку value отображать без пересчёта; «0» — значение, null — отсутствие данных. series содержит label и points `{ id, label, value: number | null }`; передать её в готовый `<LineChart series={series} />`. Общий график уже обрабатывает пустоту, один элемент, равные значения, нули и разрывы при null.

В примерах администратора выбрать «Сводка отделения · #6» и три набора. Примитив отдельно доступен в «График готовых данных». Проверить ноль/отсутствие и длинные подписи; приложить состояния и результаты check/check:web. Новый пакет графиков, формулы показателей и экспорт отчёта не добавлять.

## #7: информационный диалог

Импорт типа: `InfoDialogViewProps` из `@psycho/ui-web/contracts`. Для композиции импортировать `DialogRoot`, `DialogTrigger`, `DialogPanel` из `@psycho/ui-web`. Экспорт: `InfoDialogView`.

Props: open, title, children, trigger и onOpenChange. trigger — один ReactElement, принимающий ref и обработчики (в готовом примере это Button). Расположить trigger внутри `DialogTrigger asChild`, используя управляемый DialogRoot; заголовок и содержимое передать в DialogPanel. Это дополнение первоначального минимального контракта необходимо для возврата фокуса.

Механика фокуса, Escape, overlay, portal и закрытия уже подготовлена. Не писать свой focus trap или клиническое подтверждение. В примерах врача выбрать «Информационный диалог · #7»; работа базового примитива видна в «Поля и базовый диалог». Выбор long даёт длинное содержимое. Проверить открытие/закрытие, повторное открытие, Tab/Shift+Tab, Escape и возврат фокуса. В PR приложить короткую запись и результаты check/check:web.

## #8: синтетические данные

Единая схема: packages/ui-web/src/contracts/presentation.ts, экспорт presentationFixtureSchema. Валидатор: scripts/check-fixtures.ts. Разрешены только три перечисленных JSON-файла, а не код схемы или валидатора.

Корень содержит schemaVersion: 1, scenario, patients и department. scenario совпадает с именем файла без расширения: normal, empty, long. Все объекты строгие; неизвестные поля отклоняются. Идентификаторы имеют префикс demo-, содержат латинские буквы/цифры/дефисы и уникальны в своём массиве. Подписи непустые, secondaryText допускает пустую строку. Числа графика конечные; null допустим.

Наборы уже существуют; изменения выполняются только в рамках новой или действующей issue с критериями приёмки. Не добавлять диагнозы, дозировки, медицинские пороги или ожидаемые клинические решения. Использовать явные обозначения учебных пациентов, без реальных имён и других персональных данных. Валидатор проверяет структуру, а вымышленность проверяется также просмотром PR.

Запустить check и check:fixtures. При просмотре выбрать три набора в стенде; проверить список пациентов, показатели и переданную серию графика, включая пустоту и длинные подписи. В PR перечислить покрытые случаи. Общую схему и конфигурацию стенда ради изменения набора не менять.

## Ограничения каркаса

Состояние стенда примеров хранится в памяти вкладки. Журнал из последних 20 действий — средство разработки, а не медицинский аудит. Навигация по hash переживает перезагрузку, но данные выбора не сохраняются. Это ограничение стенда, а не серверного или локального рабочего места врача. Роли в названиях приложений не являются авторизацией. Рабочие схемы доступа, клинические правила и интеграция остаются ответственностью главы разработки.
