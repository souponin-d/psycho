# 0001. Инструменты проверки репозитория

Дата: 15 октября 2026 года.
Статус: принято для этапа подготовки.

## Контекст

Нужны одинаковые проверки на Windows и Linux до выбора стека приложения. Используем Node.js 24 только для инструментов репозитория, Prettier для форматирования и remark для Markdown-ссылок.

## Решение

Версии инструментов закреплены в `package.json` и `package-lock.json`. Проверка ссылок работает офлайн, проверяет GFM-таблицы и определения ссылок. Исходный исследовательский документ исключён из форматирования, но проверяется remark.

В `unified-args`, транзитивной зависимости `remark-cli`, закреплён `chokidar@5.0.0` через scoped override. Версия `chokidar@3` приносит `braces`, для которой npm audit сообщает [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm); исправленной версии `braces` на дату настройки нет. Текущие проверки запускают remark для каталогов и не используют режим наблюдения.

## Последствия

Команды проверки и обработка русских имён файлов проверяются на корректных и ошибочных примерах. Совместимость разового запуска CLI с override проверяется после установки из lockfile. Поддержка `remark --watch` не входит в текущие команды; новые версии chokidar не раскрывают glob-шаблоны, поэтому при добавлении такого режима его нужно проверить отдельно.

Override пересматривается при обновлении `remark-cli` или `unified-args`, когда их собственная зависимость от chokidar будет обновлена. Стек приложения этим решением не определяется.
