# Реализация личного пути пациента

> **Статус документа:** Исторический план задачи. Поручения, целевые пути, чекбоксы и ограничения описывают исходную постановку, а не состояние текущего main. Сохранён для требований и прослеживаемости; не использовать как инструкцию запуска. [Текущее состояние](../../status.md).

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** выпустить Android APK по утверждённой спецификации с календарным миром, обязательными заданиями, локальными уведомлениями и сохранением данных.

**Architecture:** локальная модель терапии и событий, транзакционное хранилище и независимый расчёт закрытых дней; UI читает проекции. Связь с врачом моделируется. Мир — настоящий вертикальный ScrollView с датированными точками; косметические данные не подменяют медицинские факты.

**Tech Stack:** React Native / Expo SDK 55 / TypeScript / Expo Router. Текущие SVG, локальные шрифты и изображения. Совместимые адаптеры SQLite/уведомлений добавляются точными версиями после проверки SDK; без backend-изменений.

**Spec:** [Утверждённая спецификация](../specs/2026-10-24-patient-journey-design.md), утверждение владельца в чате «ПРИЛОЖЕНИЕ» после коммита `5e9f7fc`.

## Global Constraints

- Выполнение поручено в текущем чате, последовательно исполнителем. Не запрашивать повторное утверждение плана как замену уже полученному поручению.
- Обновлённые макеты и движущиеся примеры спутников показать и согласовать **до переноса визуального решения в приложение и окончательной сборки**.
- Все приёмы + обязательный отчёт + назначенные на дату тесты; граница строго 00:00 по местному времени. Ретрозаполнение не восстанавливает серию.
- Карта движется по календарю, включая пропуски; мир и награды не сбрасываются. Награда за 5/7 завершённых дней, без валюты.
- Результаты клинических тестов скрыты от пациента во всех поверхностях; полные русские формы, никаких самодельных сокращений или клинических интерпретаций.
- Только синтетические сведения. Приглашение/обращения/терапия моделируются; уведомления, хранение и графики настоящие. Чат не развиваем.
- Существующие `site/index.html` и `site/styles.css` изменены другим направлением: не включать в свои коммиты и не перезаписывать.
- Перед кодом приложения — отдельная задача/ветка по правилам репозитория с сохранением мобильной базы; проверить attached worktrees и `git status`. Не пушить/создавать PR без поручения.
- Сохранять package ID `ru.syncli.patient.demo` и ключ локального обновления; без очистки данных для удобства проверки.

## Review Focus

1. Полночь при закрытом приложении и откат даты: воспроизводимый итог, без повторного зачёта/награды — задача 1.
2. Авария между сохранением приёма и выдачей предмета: атомарность и однократность — задача 2.
3. Устаревшее/дважды нажатое уведомление: один факт и отсутствие восстановления прошлой серии — задача 6.
4. Исправление/удаление старых записей и смена версии формы: история точна, игровой итог стабилен, график не выдуман — задачи 3 и 5.
5. Смена спутника/одежды во время движения и уход в фон: нет пропавших слоёв, циклов и сброса инвентаря — задачи 7 и 8.
