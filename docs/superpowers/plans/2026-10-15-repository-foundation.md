# Подготовка репозитория — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Подготовить воспроизводимые проверки и понятный порядок командной работы до получения официального кейса.

**Architecture:** Готовые CLI проверяют форматирование и локальные Markdown-ссылки. Одинаковые npm-команды работают локально и в GitHub Actions на Windows и Linux.

**Tech Stack:** Node.js 24, npm, Prettier, remark-cli, remark-gfm, remark-validate-links, remark-lint-no-undefined-references, GitHub Actions.

**Spec:** Пять пунктов подготовки, согласованные в чате 15 октября 2026 года: README, настройки файлов, CI, шаблоны задач/PR и место для ТЗ/гипотез/решений. Пользователь поручил приступить; выполняем весь пакет в этой сессии.

## Global Constraints

- Исходное ТЗ `docs/Клинический-компас_исходное-ТЗ.md` сохраняется без изменений.
- Node.js используется для инструментов репозитория; стек приложения пока не выбран.
- Проверки ссылок работают офлайн и включают файлы, заголовки и определения ссылок.
- CI запускается для PR и push в `main`, имеет права только на чтение и тайм-аут.
- Материалы для команды пишутся по-русски; демонстрационные данные в будущих прототипах должны быть вымышленными.
- Результат оставляем для просмотра в рабочей ветке; публикация и изменение удалённых настроек не входят в этот этап.

## Review Focus

- Кириллица, пробелы и URL-кодирование в локальных ссылках должны поддерживаться.
- Ошибки в заголовках другого документа и внутри GFM-таблиц должны завершать проверку с ненулевым кодом.
- Исключение исходного ТЗ из форматирования не должно исключать его из проверки ссылок.
- Настройки должны одинаково работать с LF на Windows и Linux.
- Граница между подготовительным документом и официальным ТЗ должна быть видна команде.

## Решения исполнения

- Работа выполняется в ветке `codex/repository-foundation` в текущей папке: исходный документ ещё не добавлен в Git и остаётся на месте.
- Проверяем конфигурацию реальными успешными и ошибочными примерами; отдельный тестовый фреймворк для настроек не добавляем.
- Статус фактической проверки и оставшиеся действия на GitHub будут указаны в итоговом сообщении.
- Проверка зависимостей обнаружила уязвимую цепочку `unified-args → chokidar@3 → braces`. Добавлен scoped override; причина и ограничения записаны в [решении 0001](../../decisions/0001-repository-tools.md). Повторный `npm audit` показал 0 уязвимостей.
- Установка из lockfile, `npm run check` и 11 проверок на корректных/ошибочных примерах прошли локально на Windows. Запуски GitHub Actions на удалённых runners ещё не выполнялись.
- Независимое ревью не обнаружило блокирующих или иных требующих исправления замечаний; проверяющий повторил `npm run check`, `git diff --check`, сверил lockfile, override и контрольную сумму исходного ТЗ. Внешние источники, режим наблюдения и удалённые настройки обоснованно оставлены за рамками этого этапа.
