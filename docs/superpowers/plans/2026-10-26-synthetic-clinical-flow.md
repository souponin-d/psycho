# Оценка → рекомендация → решение: синтетический контур MI03–MI13

> Для исполнителя: использовать `superpowers:executing-plans` в текущей ветке. Пользователь поручил выполнить весь описанный объём; повторное согласование постановки не требуется. Итоговый review — отдельный read-only reviewer.

**Цель:** законченный врачебный поток на синтетике в web, IndexedDB и API, с общими результатами, рекомендациями, планом, безопасностью и изменениями с прошлого контакта.

**Архитектура:** дополнительный `PatientRecord.workflow` и команды `workflow.*`, чистый домен TypeScript и зеркальная проверка ASP.NET. Существующие факты, план, направления и приёмы сохраняются. Учебная семипунктовая форма с ответами 0–3 является техническим эталоном, не утверждённой GAD-7. Источник `synthetic-followup/synthetic-7-v1`, статус `synthetic-only`, клиническое утверждение отсутствует. API разрешает учебные команды только в Development; производственная активация не добавляется.

**Стек:** существующий React/TypeScript/Vite, ASP.NET Core 10, PostgreSQL. Без новых зависимостей.

**Спецификация:** [минимальный ввод](../specs/2026-10-26-doctor-minimal-input-design.md), [MI03–MI13](2026-10-26-doctor-major-update.md).

## Границы и решения

- Все учебные результаты и предложения явно обозначены; никакого выдуманного медицинского утверждения или порогов риска. Полнота и арифметика проверяются сервером; пропуск/отказ не равны нулю.
- Рекомендации формируются по техническим основаниям: поступление результата, неполнота, непроверенные факты и прямой ответ о безопасности. Клинический смысл числового изменения не интерпретируется автоматически.
- Один объект рекомендации виден в карте, приёме, рабочем дне и плане. Изменение основания помечает прежнее предложение устаревшим, сохраняя решения и последствия.
- Принятие создаёт проект обычного плана/направления, отдельное врачебное подтверждение выполняет действие; лекарство не назначается автоматически. Повтор не создаёт дубль.
- Безопасность — отдельная очередь с доставкой только в локальную очередь врача, принятием, оценкой и подтверждённым действием. Чтение не переводит статусы; неизвестность и отказ сохраняются.
- Повторное назначение разрешённого учебного самоопросника требует подтверждённого решения/срока; никаких врачебных шкал или внешней доставки. Будущий мобильный ввод отдельно.
- Снимок контакта сохраняет версии фактов/результаты/решения. Дельта показывает новые и спорные сведения; сроки давности не выдумываются.

## Файлы и этапы

1. `clinical-workflow.ts`, `clinical-workflow.test.ts`, `model.ts`: типы результата, рекомендации, решения, безопасности, задания; проверки полноты, сравнения, подмены, повторов, старых оснований. Сначала красные доменные тесты, затем реализация.
2. `commands.ts`, `ClinicalWorkflow.cs`, `Domain.cs`: команды и паритет API, авторство, аудит, ограничения среды; OpenAPI только генератором.
3. `tests/clinical-scenarios.json`, `clinical-scenarios.ts`: детерминированные полная/неполная/отказ/опасный признак/противоречие/без изменений; синтетические даты и происхождение. Seed и явная загрузка без удаления существующих карт.
4. `ClinicalWorkflow.tsx`, `ClinicalDecisionQueue.tsx`, `PatientView.tsx`, `PatientBrief.tsx`, `Workday.tsx`, `DoctorWorkspace.tsx`, `EncounterEditor.tsx`, `Events.tsx`, `CarePlan.tsx`: общий UI оценок, рекомендаций, решений, безопасности, изменений и проектов. Использовать существующие компоненты/токены, не менять навигацию без необходимости.
5. `scripts/verify-doctor-api.mjs`, `scripts/verify-doctor-ui.mjs`: полный цикл в PostgreSQL и браузере без API; статус среды, подмена итогов, отказ/пропуск, версии, независимые подтверждения, архив, права и повторы.
6. Документация, проверки формата/типов/контрактов, полный тестовый набор с ограниченной параллельностью, обе web-сборки, API и общий build. Итоговый read-only review и устранение существенных замечаний.

## Фокус проверки

- Поздно пришедшие ответы и другая версия не смешиваются с сопоставимым прошлым результатом.
- Отказ/пропуск/неизвестность безопасности не превращаются в ноль или заключение об отсутствии риска.
- Изменение факта после открытия решения не даёт принять устаревшее основание.
- Два подтверждения/повтор команды не создают второй план, направление или опросник.
- API не позволяет пациенту, чужой клинике/врачу или Production-среде запускать учебные команды.
