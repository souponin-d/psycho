# Рабочие пространства администратора — план реализации

> **For agentic workers:** Use superpowers:executing-plans. Выполнить задачи последовательно; согласованное поручение пользователя уже разрешает реализацию.

**Goal:** Реализовать три согласованных пространства одной учебной учётной записи и воспроизводимые сценарии для каждого.

**Architecture:** Локальная схема admin demo и JSON-наборы задают задачи, сотрудников и готовые отчётные периоды. Состояние одной сессии хранится над представлениями ролей; hash задаёт раздел, ключ набора сбрасывает сессию. Собственная оболочка admin не меняет поведение общего AppShell врача.

**Tech Stack:** React, TypeScript, Vite, Zod, CSS Modules, существующие Vitest/Testing Library.

**Spec:** [Согласованный дизайн](../specs/2026-10-20-admin-workspaces-design.md).

## Global Constraints

- Без новых зависимостей, API, localStorage, клинической логики и настоящего управления доступом.
- Не менять presentation-компонент #6, схемы участников, веб врача и файлы лендинга.
- Только синтетические данные и русский интерфейс; существующие суммы 24/31 и соответствие врачу Д-01 сохраняются.
- Отдельная ветка; main не изменяется. Публикация и PR — только в разрешённом пользователем объёме.

## Review Focus

1. Переключение разделов размонтирует представление: состояние остаётся у сессии, не теряет черновик.
2. Повторное выполнение или сохранение без изменений: не дублирует журнал и счётчики.
3. Пустой период/разрыв: отсутствующее значение не становится нулём, отчёт явно неполон.
4. Некорректный hash или недоступная роль: понятное восстановление без показа другого пространства.
5. Изменение fixture/сброс: никакие локальные правки не мутируют импортированный JSON.
