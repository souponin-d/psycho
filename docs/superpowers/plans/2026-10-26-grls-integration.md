# ГРЛС: план подключения актуальных препаратов

> **Статус документа:** Исторический план задачи. Поручения, целевые пути, чекбоксы и ограничения описывают исходную постановку, а не состояние текущего main. Сохранён для требований и прослеживаемости; не использовать как инструкцию запуска. [Текущее состояние](../../status.md).

> **For agentic workers:** Use `superpowers:executing-plans`; выполнять в текущей ветке, сохранять чужие изменения. Применять TDD; итоговый технический review не равен клиническому одобрению.

**Goal:** Поиск и выбор актуальных препаратов из предоставленного полного архива ГРЛС в кабинете врача, локальном режиме и API; сохранение истории назначений.

**Architecture:** Импорт всех восьми XLSX с проверкой заголовков, даты, SHA-256 и числа строк. Общий сжатый статический каталог актуальных регистраций загружается браузером без клинического API и тем же файлом читается ASP.NET Core. Выбор сохраняется версионированным снимком в необязательном `PlanItem.medicine`; старые текстовые назначения не сопоставляются автоматически. Подтверждённые записи остаются неизменяемыми, замена выполняется через `replacesId`.

**Tech Stack:** существующие React/TypeScript/Vite, ASP.NET Core 10/PostgreSQL, REST/OpenAPI; Node.js 24, ExcelJS 4.4.0 из существующего workspace администратора, gzip.

**Spec:** запрос пользователя в этом чате и [исследование источника](../../research/2026-10-26-grls-source.md). Архив `grls2026-10-23-1.zip`, SHA-256 `118c99f66d3f57d93bef85a047f288edb3b73c7a89fddf54f530bf5eb99da88d`.

## Границы и решения

- Только актуальные для новых выборов: «Действующий», «Выдано по правилам ЕАЭС», «Действует, на подтверждении государственной регистрации», «Действует, в иностранных упаковках». Исторические/исключённые/истёкшие/приостановленные не выбираются. Даты окончания и аннулирования учитываются отдельно; снимок не выдаётся за живую синхронизацию.
- Статус регистрации отделён от статуса назначения. Выбор препарата не подтверждает назначение. Дозу и режим вводит врач.
- Инструкции не импортировать; существующее поле и правила его проверки не менять.
- Файлы: новые `scripts/import-grls.mjs` и тесты, `workspace/grls.ts`, `MedicinePicker.tsx`, общий каталог `public/catalogs/grls.json.gz` и манифест. Совместимые изменения в `model.ts`, `commands.ts`, `CarePlan.tsx`, `Domain.cs`, новый `GrlsCatalog.cs`, `Program.cs`, генератор OpenAPI. Проверки в существующих API/UI сценариях и документация.

## Реализация

1. Тесты неполного/неизвестного статуса, структуры, даты, формул, повторных строк. Воспроизводимый импорт, подсчёт всех строк и сохранение исходных статусов в манифесте; сверить полный архив независимым чтением.
2. Общая модель снимка препарата, асинхронный локальный поиск с пагинацией, проверка точного снимка и исторического удержания только в той же записи. Тесты поиска/недопустимого выбора/истории.
3. Защищённый поиск API, проверка сервером выбранного препарата при сохранении и подтверждении, совместимый сгенерированный контракт. История подтверждённого плана неизменяема.
4. Выбор в существующей форме, показ МНН, формы, РУ и статуса, обработка загрузки/ошибки/пустого результата. Регистрационный снимок виден после сохранения и при просмотре плана.
5. Web/fixtures/API build и интеграционные проверки, браузерный локальный сценарий с заблокированным API и перезагрузкой, итоговая документация и review.
