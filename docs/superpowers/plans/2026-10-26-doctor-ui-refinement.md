# Упрощение кабинета врача — план реализации

> **Статус документа:** Исторический план задачи. Поручения, целевые пути, чекбоксы и ограничения описывают исходную постановку, а не состояние текущего main. Сохранён для требований и прослеживаемости; не использовать как инструкцию запуска. [Текущее состояние](../../status.md).

> Для исполнителей: выполнять по задачам с проверкой результата; независимые части допускают параллельную работу.

**Цель:** реализовать согласованные 26 октября правки кабинета врача, сохранив историю и работающую связь с VPS.

**Архитектура:** существующие React-компоненты и CSS-токены. Разделить содержимое обзора и плана; убрать повторяющиеся пояснения, сохранив происхождение данных, аудит и подтверждения действий. Ограничение возраста дублируется в локальной модели и API. Совместимое расширение `WorkflowSubmission.visitId` связывает опросник с открытым приёмом; графики и снимки используют сохранённый результат без пересчёта.

**Стек:** React, TypeScript, Vite, ASP.NET Core 10.

**Спецификация:** список правок пользователя и уточнения в текущем чате. Пользователь подтвердил реализацию, включая разделение вкладок.

## Ограничения и решения

- Возраст 18–120 лет включительно, на текущую дату. Будущие даты и несовершеннолетние отклоняются; старые записи не удаляются.
- «Обзор»: данные пациента, результаты тестов и рекомендации. «Лечение и план»: принятые решения, назначения, приверженность, контакты, направления. Общую клиническую поддержку убрать из плана.
- Короткие русские подписи; «Риски», «Уведомления», «Библиотека», «Редактировать», «Дополнительная информация». «Заключение и договорённости» пока не менять.
- Клинические сведения: компактные строки Да / Нет / Неизвестно. Отсутствие ответа не означает отрицание. Источники и детали раскрываются по запросу.
- Удаление элементов интерфейса не стирает прежние значения и аудит. Не изменять клинические пороги и правила.
- Полные тексты библиотеки: только имеющиеся Markdown, без преобразования PDF и без добавления редакционных инструкций в клиническую логику. Исторические источники скрыты из списка, доступны по старым ссылкам.
- Использовать существующие доступные диалоги; фиксированный подвал профиля, без верхней кнопки закрытия, с Escape и отменой. Удаление плашек доступно клавиатурой и на сенсорном экране.

## Задачи

1. **Навигация, рабочий день, календарь.** `DoctorWorkspace.tsx`, `Workday.tsx`, `Events.tsx`: убрать отдельный хедер и дубли заголовков; дата/статус в содержимом, Демо-данные только для локального режима. Сегодняшние приёмы наверх. Уведомления без лишних пояснений. Планирование из календаря: выбор пациента и форма приёма с датой. Проверить основной и пустой сценарии.
2. **Клинические панели и приём.** `ClinicalSupportPanel.tsx`, `ClinicalWorkflow.tsx`, `EncounterEditor.tsx`, `PatientBrief.tsx`, `CarePlan.tsx`: компактные сведения, короткие подписи, скрыть нерелевантные ссылки, риски вместо безопасности, убрать снимок контакта из приёма и общий блок изменений, вопрос пациента перед приёмом. Убрать ручные метаданные встречи, сохранив их значения; решение пациента вместо непонятного согласия/отказа. Не переименовывать заключение.
3. **Библиотека.** `SourceLibrary.tsx`, отдельные файлы просмотра Markdown и стили: карточка открывает источник, исторические скрыты, паспорт без технических полей, тексты существующих Markdown с безопасным рендерингом. Проверить ссылки старых записей и отсутствие исполнения HTML/инструкций.
4. **Пациент, профиль, возраст.** `PatientView.tsx`, `PatientDirectory.tsx`, `PatientForms.tsx`, `PatientContext.tsx`, `TerminologyPicker.tsx`, `ui/Elements.tsx`, CSS, `commands.ts`, API Store: разделение вкладок, сведения выше, правильный порядок анамнеза, чипы МКБ, фиксированные кнопки и возраст. Тестировать границы 18/120, дни рождения, отказ на 17/121, API/local одинаково.
5. **Шкалы и наблюдение.** `Dynamics.tsx`, `AssessmentForms.tsx`, существующие формы шкал: оба входа — вопросы с подсчётом и готовый результат; понятные названия и переходы. Изменения лечения свернуть и скрыть при пустоте. Не придумывать отсутствующие тексты/ключи.
6. **Проверка и PR.** Целевые тесты, `npm run check`, `npm run check:web`, `npm run check:fixtures`, API на изолированной БД для возраста; браузерная проверка, клавиатура/узкий экран, скриншоты. PR в main без прямого push и без самостоятельного merge.

## Фокус проверки

- Неизвестное клиническое значение не превращается в «нет» после компактного редактирования.
- После удаления старых полей из интерфейса они не теряются при сохранении профиля/приёма.
- Календарь не создаёт запись не тому пациенту; закрытие формы ничего не сохраняет.
- Возраст проверяется на дату дня рождения, включая високосные даты.
- Вкладки и прямые ссылки показывают разные ожидаемые блоки; функции принятия решений не исчезают.

Живой статус и итоговые доказательства ведутся в issue/PR, этот документ описывает объём.
