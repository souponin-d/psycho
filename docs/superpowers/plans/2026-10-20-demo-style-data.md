# Единая стилистика и данные демо: план реализации

> Исполнение: агент реализует задачи последовательно в этой сессии через superpowers:executing-plans; итоговый diff проходит отдельное техническое ревью. Дизайн-скиллы не используются по указанию пользователя.

**Цель:** привести обе публичные демонстрации и стенды примеров к стилю сайта, наполнить основные экраны качественными синтетическими данными.

**Основание:** поручение пользователя от 20 октября 2026 года; [предыдущее подключение демо](../../verification/2026-10-20-site-demo-entry.md), [командные границы](../../team/web-components.md).

**Архитектура:** общая тема и оболочка ui-web; отдельные демонстрационные экраны в apps/web-doctor/src/demo и apps/web-admin/src/demo. Каждый получает свои normal/empty/long JSON по собственной строгой схеме. Они не являются API DTO и не меняют контракты presentation-задач участников. Используется существующий React/TypeScript/Vite, Zod, Radix Dialog; новые зависимости не нужны.

## Ограничения и предмет проверки

- Только вымышленные обозначения пациентов и врачей, фиксированный снимок 20.10.2026; без персональных данных, диагнозов, дозировок и правил риска.
- Состояние поиска, выбора и сценария живёт в памяти. Клинических действий, HTTP и сохранения нет.
- Представления #5–#7 и JSON задачи #8 сохраняются для их исполнителей; общая тема применяется и к ним. Публичные демо — отдельная область главы разработки.
- Нулевые значения должны отличаться от отсутствующих; длинный текст переносится; неверный набор показывает ошибку, а не выдуманные данные.
- Проверить: скрытая фильтром запись не остаётся в области выбора; смена набора сбрасывает поиск/выбор; id уникальны и связанные записи согласованы; показатели согласуются с источником; оба приложения и их возврат на сайт работают на 360/768/1280 px.
