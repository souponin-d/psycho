# Источник полного ГРЛС: проверка доступности

Дата: 26 октября 2026 года. Задача пользователя: подключить полный ГРЛС к поиску и выбору препаратов в кабинете врача, локальном режиме и API; сохранить историю назначений и статусы регистрации. Массовые инструкции исключены из этого этапа.

## Подтверждённые источники

[Минздрав описывает два способа выгрузки](https://minzdrav.gov.ru/special/documents/9892-opisanie-tehnicheskih-trebovaniy-k-vzaimodeystviyu-informatsionnoy-sistemy-posrednicheskoy-tsifrovoy-platformy-s-gosudarstvennoy-informatsionnoy-sistemoy-reestrom): ZIP с XLSX на основном портале и сокращённый набор ЕСНСИ. Возможность скачать файл не подтверждает равенство содержимого этих публикаций.

[Основной портал](https://grls.minzdrav.gov.ru/grls.aspx): по описанию Минздрава ZIP включает отдельные XLSX по статусам РУ с одинаковой структурой, в том числе торговое название, МНН, формы выпуска, держателя, даты и производственные сведения. На текущем этапе именно этот источник необходим для выполнения задачи.

[ЕСНСИ 26361](https://esnsi.gosuslugi.ru/classifiers/26361/data): публичный паспорт получен успешно. Код `Svedeniya_GRLS`, название «Сведения ГРЛС для Единого сервиса ОПЦП», ревизия 127, обновление `2026-10-23T06:30:07.584066Z`. Первая страница сообщает `total=29317`. Структура содержит только:

1. Номер регистрационного удостоверения.
2. Дату регистрации.
3. Дату окончания действия.
4. Торговое наименование.
5. Служебный autokey.

В этой структуре отсутствуют МНН, форма выпуска, производитель и явный статус регистрации. Значение даты окончания `-` не превращается в утверждение о действующей регистрации. Набор не подходит как замена полного ГРЛС для запроса пользователя.

## Результат проверки доступа

Публичные API ЕСНСИ работают. Основной ГРЛС не загрузился через Python HTTPS и браузер; старый официальный домен и HTTP также завершились тайм-аутами соединения. Получить основной архив и сверить его полноту не удалось. Также просмотрены публичные метаданные классификаторов ЕСНСИ: найден сокращённый набор и вспомогательные классификаторы ГРЛС; полный набор с необходимыми полями не найден.

Исходные ответы исследования сохранены локально в игнорируемой `.cache/grls-source-research/`: `passport.json`, `structure.json`, `first.json`. Они не являются подготовленным каталогом приложения.

## Что требуется для продолжения

Нужен полный официальный ZIP, скачанный с основного портала, целиком с XLSX для всех опубликованных статусов, включая исторические. При получении архива проверить дату, SHA-256, состав файлов, столбцы, строки и дубли; не выдумывать число записей или статус по отсутствующим данным. Если источник публикует самостоятельные наборы препаратов и субстанций, отметить границы импорта: поиск назначения использует лекарственные препараты, а не отдельные фармацевтические субстанции.

Текущая модель назначений: `PlanItem` в `apps/web-doctor/src/workspace/model.ts`, форма `CarePlan.tsx`, локальные команды `commands.ts`, серверные команды `apps/doctor-api/Domain.cs`. Уже действуют отдельное подтверждение назначения, обязательные доза/режим/ссылка на проверенную инструкцию, запрет перезаписи подтверждённой записи и версия замены через `replacesId`. Их нужно сохранить.

Будущее подключение: один проверенный версионированный артефакт, постраничный поиск в браузере и API, точная проверка выбранной записи на сервере, снимок регистрационных сведений в назначении. Старые текстовые назначения не сопоставлять с препаратом автоматически; подтверждённые записи не переписывать при обновлении каталога. Статусы реестра хранить отдельно от статусов назначения. Новые клинические правила и автоматический подбор доз не входят в задачу.

Продуктовое подключение и проверки полного реестра пока не выполнены: доступного полного исходного архива нет. Сокращённый или сторонний набор не выдан за полный официальный ГРЛС.
