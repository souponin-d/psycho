Доменный набор проверяет арифметику без доверия присланной сумме, пропуск/отказ, сравнение версий/периодов, нормализацию часовых поясов, причины решений, отдельное подтверждение, пересмотр/отклонение проектов с сохранением истории, устаревание основания, последовательность безопасности и снимки контакта.

HTTP-набор проверяет эти команды на PostgreSQL и сопоставляет состояние с локальным доменом; отдельно отклоняет присланные сумму/утверждение/неподдерживаемую версию, повторяет каждую успешную команду потока для проверки идемпотентности и после каждого отклонения сверяет сохранённое состояние, проверяет задание и его однократное заполнение, подготовку/выдачу направления, все семь синтетических случаев, сохранность после повторного чтения и недоступность внутренних решений пациентскому API. Семь случаев: полная оценка, пропуски, отказ, прямое сообщение о безопасности, противоречие, неизменившиеся ответы, невозможность заполнения.

## Воспроизведение

После подготовки по [runbook](../doctor-workspace-runbook.md) запустите web и при необходимости отдельный Development API. Команды ниже — способ повторения, а не утверждение об их итоговом прохождении:

```powershell
npx vitest run --project web apps/web-doctor/src/workspace/clinical-workflow.test.ts --maxWorkers=1
npm run build:doctor:api
$env:DOCTOR_API_TEST_URL = 'http://127.0.0.1:5080/api'
npm run check:doctor:api
$env:DOCTOR_UI_MODE = 'demo'
$env:DOCTOR_WEB_URL = 'http://127.0.0.1:8768'
npm run check:doctor:ui
```

Для серверного браузерного повтора используйте `DOCTOR_UI_MODE=server` и локальную тестовую конфигурацию; `all` проходит оба режима. API-проверка создаёт тестовые учётные записи и карты: только изолированный синтетический стенд. Для общей передачи нужны также `npm run check:web`, `npm run check:fixtures` и `npm run check`. Скриншоты браузерный скрипт сохраняет в `.cache/doctor-screens`; в PR нужны отобранные снимки без секретов.

Ручной повтор: полная оценка 7 → 14 → решение → проект → отдельное подтверждение; затем изменение/отклонение проекта до исполнения; пропуск/отказ → отдельная безопасность по всем этапам; подтверждённое повторное задание → ответ по его ID; новый факт → устаревшее основание; перезагрузка → сохранённая история. Проверить клавиатуру и узкую ширину. Медицинскую валидность этим повтором не подтверждают.
