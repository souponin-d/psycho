## Изменение

В существующей форме назначения доступен выбор Авиандра. Используются дата рождения, аллергии, заболевания, лекарственный/репродуктивный контекст и сведения о веществах из профиля, незакрытые эпизоды и история подтверждённых лекарственных назначений. Свободный текст показывается врачу без автоматической классификации. Уточнения сохраняются в проверке конкретного назначения, не подменяя профиль пациента.

Разделены условия противопоказания, предосторожности, нехватка данных и оценка врача. Нет заключения «препарат безопасен», автоматических назначений или клинических блокировок. СКФ в индексированных единицах не сравнивается с абсолютным порогом; актуальность результата определяет врач. Граница возраста 18 лет требует сверки формулировок ОХЛП. Дозировка/режим остаются свободным вводом и отдельной оценкой врача. Список лекарств требует ручной сверки; автоматического классификатора взаимодействий нет.

Снимок `PlanItem.aviandrReview` содержит уточнения, контекст, результаты, версию/дату/URL/SHA-256 источника, автора и время. При сохранении и подтверждении локальный домен и API пересчитывают результаты. Изменённый контекст требует повторной сверки; локальный текст формы сохраняется. При выборе другого препарата проверка отсоединяется. Сервер отвергает поддельное утверждение, источник и неизвестные поля. В пациентский API внутренний снимок не передаётся.

## Воспроизведение UI

Запустите API и doctor web по [runbook](../doctor-workspace-runbook.md). Для нового скрипта нужны локальный конфиг тестовой клиники и установленный Playwright Chromium:

```powershell
$env:DOCTOR_WEB_URL = 'http://127.0.0.1:8768'
node scripts/verify-aviandr-ui.mjs
```

На данном Windows-стенде использованы `DOCTOR_DOTNET`, `DOCTOR_LOCAL_CONFIG` и `PLAYWRIGHT_BROWSERS_PATH`, указывающие на существующие локальные инструменты/конфигурацию. Секреты в отчёт, код и снимки не включены. Сценарий создаёт только синтетическую карту.

## Совместимость и передача

Новых npm/NuGet-зависимостей и SQL-миграций нет. Новое поле назначения необязательное, существующие карты работают без него. API и web этой версии поставляются вместе: прежний строгий API не принимает поле `aviandrReview` при сохранении. Для возврата к старой версии на данных с новыми проверками требуется заранее проверенное преобразование дополнительного поля на резервной копии; не удалять карты и не очищать БД/IndexedDB ради отката.

Контракт сгенерирован существующим `npm run contract:doctor`; клиент вручную не редактировался. Перед интеграцией нужен просмотр контракта/сервера главой разработки и независимое человеческое ревью. Слияние в main допускается только через PR после обязательных проверок и независимого человеческого ревью.

Перед PR коммит задачи перенесён на актуальный `origin/main` (`43ecd64`); посторонние коммиты админки и лендинга исключены. Повторно прошли `check`, `check:web` (175 тестов в 25 файлах), `check:fixtures` (61 тест), сборка API и 37 API-проверок. Код врача при переносе не менялся; браузерные результаты и снимки относятся к этой же реализации.
