# Навигация и карта мобильного приложения 0.4.5

Задача [#57](https://github.com/souponin-d/psycho/issues/57), владелец souponin-d. Реализовано по прямому поручению владельца после обсуждения.

## Изменения

История открывается круглой кнопкой в правом верхнем углу плашки «Мой путь» вместо настроек. Это отдельный защищённый экран `/history` с возвратом назад. Ссылки из карточки дня и уведомлений обновлены; настройки содержат дополнительный вход в историю для режима без игровой карты. Настройки по-прежнему доступны из заголовков остальных вкладок и редактирования цели.

Навбар: «Путь», «Лечение», «Врач», «Рядом». Раздел «Связь с врачом» показывает кнопку «Связаться с врачом» под заголовком и одну карточку «Лечащий врач» с последним сообщением. Кнопка открывает существующую форму обращения, карточка — существующую переписку. Новые учётные записи, серверные методы, индикация вымышленного прочтения или отдельные чаты не добавлены. В демо карточка предлагает подключение по коду, а форма сохраняет прежний локальный сценарий.

Из обоих вариантов лечения убрана перенесённая кнопка. Верхние заголовки основных страниц показывают названия разделов вместо «Синкли», повторные заголовки удалены. Иконки навбара обновлены в существующей SVG-системе с округлой линией.

Причина обрезания: фон рисовался под панелями, а персонаж и предметы — в отдельном укороченном viewport с `overflow: hidden`. Теперь viewport общий; панели учитываются отступами содержимого, позиционированием фона и расчётом камеры. «К сегодня» помещает текущий день в центр свободной области. Геометрия виртуализированных секций учитывает верхний отступ. Пейзажи, оригинальные цвета и размеры маскотов не менялись.

## Проверка

- Пять новых тестов сначала упали из-за отсутствующих модулей представления карточки и камеры, затем прошли после реализации. Полный `npm run check:mobile`: TypeScript, ESLint и 201 тест прошли после окончательных изменений.
- Чистая установка `npm ci --ignore-scripts --offline --no-audit --no-fund` выполнена в изолированной папке; общий TypeScript проверен её компилятором. После восстановления общих зависимостей мобильная проверка повторена успешно.
- `npm run check`: финальные форматирование, ссылки, JavaScript лендинга и полная веб-сборка прошли. Генерируемая папка `artifacts/` исключена из проверки Markdown, как уже исключена из Git; исходные документы проверяются полностью.
- APK установлен обновлением поверх 0.4.4 на `emulator-5570`, Android API 37. Font scale 1.0. `verify-navigation-android.mjs --server-config PRIVATE_JSON` прошёл: карта → история → возврат; вкладка врача → форма → возврат → переписка; заголовки лечения и помощника; доступ к настройкам; карта в тёмной теме и прокрутка.
- Тот же Android-сценарий повторён в сохранённом демо-профиле без server-config и прошёл; карточка врача предлагает подключение по коду, серверные сообщения в демо не показываются.
- Серверные сценарии использовали существующую синтетическую сессию и VPS по HTTPS. Новые сообщения и назначения эта проверка не создавала. Полная доставка данных покрыта проверками интеграции предыдущего релиза; API и VPS этой задачей не менялись.

## APK и ограничения

Android `0.4.5`, versionCode `9`, пакет `ru.syncli.patient.demo`, ABI arm64-v8a/x86_64. APK передаётся локально, в репозиторий и на VPS не загружается. SHA-256: `e51111abeef054071ac3c51da678e5ea0f918bb6fa279ce7ef6fce329aa9b235`. Подпись совпадает с 0.4.4: SHA-256 сертификата `fac61745dc0903786fb9ede62a962b399f7348f0bb6f899b8332667591033b9c`.

Проверены HTTPS-origin VPS в Hermes bundle, отсутствие локального тестового origin, отсутствие `debuggable` и `usesCleartextTraffic`. iOS не собирался. Проверка на эмуляторе не заменяет повторную проверку на исходном телефоне пользователя. Самопроверка ИИ не является независимым человеческим одобрением PR.

Миграций данных и новых зависимостей нет. Откат: прежняя версия исходников через PR и APK с совместимой подписью; для Android потребуется обычная процедура обновления с более высоким versionCode либо отдельная согласованная переустановка. Удалять пользовательские данные ради отката не требуется и автоматически не выполняется.
