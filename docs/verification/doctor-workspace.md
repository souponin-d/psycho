# Рабочее место врача — реализация и приёмка

Дата: 22 октября 2026. Ветка: `codex/doctor-workspace`. Основания: [официальный кейс](../official/2026-10-15-case.md), [спецификация D01–D25 / R01–R24](../specifications/doctor-web/2026-10-22-doctor-web-specification.md), [документ «Врач-пациент»](../specifications/doctor-web/patient-journey-reference.md). Названия, редакции, страницы и SHA-256 всех 38 использованных источников сохранены в [реестре](../specifications/doctor-web/2026-10-22-source-register.md). Исходные ограниченные материалы и данные пациентов в Git не добавлены.

## Что можно выполнить

Врач создаёт карту и эпизод, заполняет анамнез/контекст/цели, регистрирует оформленные согласия, планирует и проводит приём, записывает клиническую оценку и измерения, составляет и подтверждает план, выдаёт направление, завершает приём и назначает следующий. Подтверждённая запись имеет неизменяемый снимок; уточнение оформляется дополнением. В карте доступны динамика сопоставимых измерений, лечение, дневник, НЯ/приверженность, события с этапами обработки, сообщения и документы с точными цитатами. Рабочая печать регистрируется в аудите.

Это работающий вертикальный сценарий с ASP.NET Core 10 и PostgreSQL, а также отдельным учебным режимом IndexedDB. Клиническая активация автоматических правил и выпуск для реальных пациентов имеют отдельные условия ниже. Технические проверки не объявляются клинической апробацией или подтверждением соответствия всем нормам.

## Воспроизведение

Команды, параметры и порядок запуска приведены в [runbook](../doctor-workspace-runbook.md). Скрипты создают только синтетические данные. `.cache` содержит локальные результаты и снимки экрана, но не является публикуемым артефактом.

- `npm ci --ignore-scripts`: воспроизведено после изменения lockfile. Первый запуск встретил Windows file lock от Vite; после остановки принадлежавших задаче dev-серверов повтор успешен.
- `npm run check:web`: успешно, 127 тестов в 14 файлах, контракт, TypeScript и doctor/admin production builds. В том числе 51 тест подготовительной арифметики шкал: пропуски, обратные пункты, нулевой знаменатель, противоречивые/отсутствующие ключи. Отдельно проверены потеря ответа, стабильный commandId, конфликт редактора, ввод во время сохранения, отказ сети и восстановление сессии. Шесть сценариев проверяют формы после обновления другим врачом: сравнение профиля/эпизода/фактов, сохранность локального текста, запрет подтверждения невидимых изменений и перезаписи уже подтверждённого назначения.
- `npm run check:doctor:forms` (также входит в `check:web`): синтетические проверки извлечения таблиц, кодов, пустых подписей и границ ключа успешны. Локально проверены хеши 18 оригиналов и побайтовая воспроизводимость 19 JSON (18 форм и отчёт); тексты остаются вне Git.
- `npm run check:fixtures`: 34 теста и проверка схем трёх наборов синтетических fixtures.
- `.NET build`: 0 предупреждений, 0 ошибок; сервер действительно запущен с PostgreSQL.
- `npm run check:doctor:api`: 32 проверки успешно — вход/CSRF, создание/повтор, строгая валидация, конфликт, неизменяемость и снимок, событие/этапы, чужая клиника/врач, пациентские права, реальное поступление отчёта, согласия сообщений, исходный документ и OpenAPI; дополнительно сохранение подготовительной формы, запрет поддельного утверждения/хеша/ответа и замены источника у существующего черновика, авторизованная выдача подготовленной формы. На этом стенде S23 фактически выдана с семью вопросами; CI без оригиналов проверяет корректный ответ об отсутствии файла.
- `npm run check:doctor:ui`: успешно, по 10 групп сценариев в demo и server, включая профиль → эпизод → согласия → приём → измерение → подтверждённый план → завершение/reload/печать PDF → следующий приём → дневник/события → сообщение/документ → динамика → форма GAD-7, арифметика, сохранение/reload без попадания в клиническую динамику → мобильная навигация.
- `npm run check:doctor:restore`: dump восстановлен в новую БД; семь таблиц совпали по количеству и хешу содержимого. Исходная БД не перезаписывалась.
- `npm run check`: успешно — форматирование, ссылки, синтаксис landing JS и общий demo build. Разделение загрузки рабочего места и прежних примеров убрало предупреждение о монолитном JS-файле больше 500 KB.

Снимки только с синтетическими данными: [рабочий день](doctor-workspace-images/workday.png), [завершённый приём](doctor-workspace-images/visit.png), [динамика](doctor-workspace-images/dynamics.png), [телефон 360 px](doctor-workspace-images/mobile.png), [проверка подготовительной формы](doctor-workspace-images/assessment-review.png). Полные исходные тексты вопросов на публикуемых снимках отсутствуют.

При финальной проверке обнаружены две нестабильности окружения/проверок. Запуск уже собранного сервера и создания тестовых пользователей переведён с повторной оценки MSBuild через `dotnet run --no-build` на прямой запуск DLL после сборки; повтор API успешен. Клавиатурный автотест теперь ожидает фактический начальный фокус вложенного Radix-диалога перед Escape, сохраняя проверки возврата фокуса и локального текста; отдельный проход 20 открытий/закрытий успешен. Эти исправления не ослабляют серверные или пользовательские критерии.

Набор `npm audit` всего монорепозитория сообщает 29 проблем (8 moderate, 21 high) в существующем дереве Expo/React Native/Metro/Jest. Автоматический breaking upgrade мобильного стека не выполнялся. Это отдельное открытое замечание к общей поставке, а не «чистый аудит». .NET/веб-пакеты проверяются отдельно при подготовке выпуска.

## Условия передачи и клинической активации

Технические данные и врачебные записи можно заполнять полностью в реализованном сценарии. Автоматические медицинские выводы нельзя подменить ручным вводом и объявить соответствующий целевой критерий закрытым. До их включения нужны: врачебное утверждение сценариев D01, версии/ключи D05/D08, проверенные инструкции и правила D13, регламент реагирования D17 и решения R24. В частности, противоречия GAD/HCL/других форм и отсутствующая страница схемы локальной КР депрессии остаются в реестре как ограничения.

Для реальных данных владельцу клиники и главе разработки нужно записать разрешённый контур, основания/операторов обработки, полномочия, правила выдачи/хранения/подписания, дежурства и резервирование. Подготовленные технические средства не заменяют этих решений. Клинические изменения требуют явного одобрения врача по `AGENTS.md`.

В main ничего не публикуется и не сливается. Публикация/PR — только в согласованном объёме; серверные контракты и доступ требуют ревью главы разработки, клиническое содержание — отдельной клинической валидации.
