# Кабинет врача после мобильной интеграции 0.4.4

> **Статус документа:** Историческое свидетельство: результаты и ограничения относятся к указанной ниже дате и версии. Они не являются текущим статусом всего продукта. [Текущее состояние](../status.md).

Задача [#55](https://github.com/souponin-d/psycho/issues/55), владелец souponin-d. База ветки — `f2d80da`, актуальный на начало работы `main` с PR №50–54. Работа выполнена на синтетике 27 октября 2026 года.

## Изменения

- При дистанционной коррекции доступны дозировка, обоснование и причина изменения. Остальные параметры заблокированы; выбор дистанционного приёма восстанавливает их из исходного назначения. Существующая проверка допустимости вызывается до отправки: без исходного назначения этого врача сохранение недоступно. Выбор очного приёма возвращает обычный режим.
- При восстановлении другого исходного препарата удаляется оставшаяся проверка Авиандра. Крайний случай найден при отдельном просмотре diff и покрыт тестом.
- Мобильные самоотчёты одной версии формы и `entityId` объединены: сверху последняя полученная запись, предыдущие — в «Истории изменений». Дата пациента не определяет порядок исправлений. Объекты и их порядок в сохранённой карте не меняются. Просмотр отмечается отдельно для каждой версии; прежний вопрос безопасности остаётся видимым предупреждением.

Контракт, API, БД, источники и клинические правила не изменены. Новые клинические ветки не активируются.

## Публичный обмен: настоящий программный канал мобильного приложения

Врачебные запросы выполнялись через `https://syncli-main.layero.app/api`, пациентские — напрямую через `https://176.32.37.10/api`. Использован `createPatientChannel` из исходников мобильного приложения с его декодерами. Cookies сессий разделены, проверка HTTPS сохранена. Релиз обеих точек — `20261027-integration-90ee18d`.

Команда: `node --use-env-proxy scripts/verify-public-patient-exchange.mjs <private-config.json> --write-synthetic`. Приватный файл содержит существующие реквизиты, `patientId` и код; они не включены в Git. Для маршрута к VPS использовался существующий локальный CONNECT-прокси; Layero обращался напрямую. Скрипт не запускает seed, SQL или очистку БД, требует явного флага и проверяет явно синтетическое название карты.

Все восемь групп сценариев прошли:

| Сценарий                                        | Результат                                                                   |
| ----------------------------------------------- | --------------------------------------------------------------------------- |
| Вход врача через Layero и пациента через VPS    | Одна и та же синтетическая карта                                            |
| Переписка в обе стороны, повтор команды         | Ответ виден пациенту, повтор без дубля                                      |
| Черновик → подтверждение препарата → расписание | Черновик пациенту не виден; подтверждённое назначение и расписание получены |
| Самоотчёт → исправление → повтор                | Две исходные версии без третьего дубля; категория сна не превращена в часы  |
| Выданный GAD-7                                  | Ответы и связь с заданием сохранены; повтор без дубля                       |
| Выданный PHQ-9                                  | Ответы и связь с заданием сохранены; повтор без дубля                       |
| «Принят» → повтор → «пропущен»                  | Одна отметка, две версии истории, происхождение «пациент»                   |
| Новый вход пациента                             | Данные восстановлены мобильными декодерами                                  |

Наступление слота ожидалось по реальному времени; подтверждение назначения и БД не менялись задним числом. Первая попытка расписания отклонена из-за несовпадения часов станции и сервера: скрипт исправлен для использования HTTPS Date сервера и сохранённого `confirmedAt`. Отклонённая команда не создала расписание. Технические записи помечены «Синтетическая проверка #55» и оставлены с аудитом.

## Установленный APK и браузер

Проверен уже установленный APK 0.4.4 на Android-эмуляторе `emulator-5570`; приложение не пересобиралось и не переустанавливалось.

1. Экран «Лечение» получил подтверждённый препарат и время из серверного расписания. Отметка исправлена с «пропущен» на «принят» с подтверждением в приложении. Через Layero проверены итоговый статус и три версии истории.
2. Из «Связи с врачом» отправлено сообщение `APK55 test public exchange`. Оно найдено через Layero и показано в карте как вопрос пациента.
3. Заполнен самоотчёт с меткой `APK55report`. APK показал «Самоотчёт отправлен врачу»; через Layero получены исходные поля и заметка, браузер показал запись в дневнике.
4. Дополнительно выданы GAD-7 и PHQ-9, оба пройдены в APK. GAD-7: семь ответов по 1, итог 7; PHQ-9: восемь ответов по 1 и пункт 9 = 0, влияние = 1, итог 8. Через Layero найден ровно один результат на каждое задание, оба задания `submitted`, `receivedBy.specialty = patient`.

Неизвестные ответы о безопасности не закрывались. Эти проверки подтверждают передачу синтетических данных, а не клиническую оценку. Браузером проверены вход врача, загрузка карты, текст APK и результаты. Новые компоненты проверены локально на копии синтетических данных; этим PR они ещё не опубликованы.

Во время работы Layero временно вернул HTTP 404 «Адрес свободен» на `/`, `/doctor/` и `/api/health`. После просьбы владельца повторить проверку кабинет и health снова вернули 200; вход и проверка данных после восстановления прошли. Настройки хостинга и VPS не менялись.

## Применение и откат

После review и обязательных checks PR сливается через GitHub в `main`, откуда Layero выполняет обычный автодеплой. Обновление API/VPS, миграции и изменение настроек не требуются. Для отката интерфейса — revert PR через новый PR; данные и аудит остаются на сервере. Самопроверка и отдельный просмотр ИИ не заменяют approve другого контрибьютора.
