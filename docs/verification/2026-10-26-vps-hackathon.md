# Публичный контур Android — VPS — кабинет врача

26 октября 2026 года. Владелец прямо поручил выполнить публикацию на имеющемся VPS. Это выполненная публикация синтетического стенда, а не продолжение только локального тестирования. `main` не изменялся и не сливался локально; отдельная task-ветка сохраняется для PR/review.

## Фактический результат

- <https://176.32.37.10/doctor/> — существующая форма врача и сохранённая кнопка учебного режима.
- <https://176.32.37.10/api/health> — HTTP 200, PostgreSQL ready.
- <https://176.32.37.10/downloads/Syncli-0.4.2.apk> — самостоятельный Android APK, HTTP 200, 130594136 байт. SHA-256: `b4e9c957ed33523e7559c9f3c9eb1676078c1dd4ada637054461f89097fcd87d`.

APK установлен поверх прежней версии на Medium_Phone / API 37 / emulator-5570, масштаб шрифта 1.0. Версия 0.4.2, versionCode 6; release без DEBUGGABLE, JS встроен в APK, адрес — публичный HTTPS, локальный HTTP-флаг выключен. ABI: arm64-v8a и x86_64. Ключ подписи пока тестовый; публичная публикация в магазине не выполнялась.

Нативный клиент вошёл по коду и получил сообщение, созданное только в БД VPS. Затем через существующую форму отправлено `VPSAndroidTest20261026`. В браузере открыт именно публичный кабинет, обращение найдено в «Наблюдение → Сообщения», врач отправил ответ. Текст «Ответ с VPS: обращение Android получено…» появился в release APK после опроса сервера. Ни Vite proxy, ни локальный API в этом обмене не участвовали.

## Проверки на фактическом VPS

Публичный TLS проверялся штатными Python HTTPS, Chromium, curl и Android без `ignoreHTTPSErrors`, `-k` или отключения проверки сертификата. Let's Encrypt YE1, SAN — IP 176.32.37.10; текущий сертификат действителен до 2 ноября 2026, 07:21 МСК. Caddy поддерживает автоматическое продление.

Проверены health, вход врача, неправильный/правильный код, серверная привязка карты, запрет doctor API для пациента, Secure cookies, отказ без CSRF, отсутствие дубля команды, получение сообщения врачом и ответ пациенту. После `systemctl restart syncli-api` и reload Caddy сохранённая secure-сессия работала без нового входа, а сообщения остались в БД. Обе службы `enabled` и `active`.

Снаружи слушают 80/443 и прежний SSH. `127.0.0.1:5080`, `127.0.0.1:5432`, `127.0.0.1:2019` остаются внутренними. Проверены права env/PFX 0640 root:syncli и keys 0700 syncli.

Создана зашифрованная копия БД и настроек, проверены расшифрование и восстановление в отдельную временную БД. Контрольная сумма внешней и серверной копий совпала: `a549e1e00ab6e2697fcd5e738ff2ede6e1d4bc1c831bfd79d83d169c94ea46b2`. Рабочая БД не удалялась и не подменялась.

Из-за маршрута VPN на проверочном компьютере браузер и эмулятор использовали ограниченный CONNECT-туннель до реального VPS через Wi-Fi. Это влияет на воспроизведение тестовой среды, но не отключает TLS и не меняет публичный origin APK.

## Границы прототипа

Данные синтетические. Полная синхронизация плана/опросников, постоянная очередь исходящих, подтверждение прочтения и медицинский production-профиль не добавлялись. Прежние аудиторские замечания зависимостей этим развёртыванием не исправлялись. Резервирование пока ручное, контроль нагрузки/регулярные восстановления — отдельная эксплуатационная задача. [Инструкция стенда](../../deployment/demo/README.md) содержит настройки, способ проверки, резервирования и отката. Код и пароли в репозиторий и APK не включены.
