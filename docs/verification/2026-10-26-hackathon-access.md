# Проверка хакатонного канала Android — сервер — врач

26 октября 2026 года. Ветка `codex/mobile-approved-ui`, изменения после `5c7732c`. Только синтетические данные. Это результат локальной интеграции, а не отчёт о работающем публичном стенде или медицинской сертификации.

## Подтверждённое поведение

Существующее поле приглашения Android проверяет код через API. Неверный код отклоняется, действующий открывает одну серверную patient-сессию. После холодного запуска тот же экран запрашивает код повторно. Повторный вход тем же кодом работает, локальный профиль и мир не сбрасываются.

Существующее «Обращение» отправлено с Android в PostgreSQL. Врач открыл ту же синтетическую карту через свою обычную форму входа, перешёл в «Наблюдение → Сообщения», увидел обращение и отправил ответ. Android получил новый ответ при опросе сервера; ответ виден и после повторного открытия обращения.

Обе кнопки деморежима сохранены. Нативная проверка локального демо-обращения показала неизменное число серверных сообщений; полученный от врача текст в демо не отображается. Локальный чат-навигатор не подключён к врачу.

Использовались Medium_Phone / API 37 / `emulator-5570`, шрифт 1.0 и существующий профиль. Изолированные PostgreSQL 55453 и API 5096, веб врача 8774. Локальный HTTP разрешён отдельным флагом только для loopback/эмулятора; публичный релиз требует HTTPS с проверяемым сертификатом.

HTTP-проверки охватывают CSRF, запрет doctor API для пациента, неподходящий код, повторное использование кода, игнорирование клиентской подмены карты/роли, отсутствие дубля команды, ответ врача, отзыв отношения лечения, выключение/просрочку доступа, запрет doctor-актора и ограничение попыток. Отдельная проверка доказала, что код не работает как обычный пароль через `/api/login`.

Два параллельных прогона `check:web` дали 199/200 и 197/200: тайм-ауты 5000 мс в неизменённых ExampleWorkbench/AnalyticsDashboard и сбой следующего assertion ExampleWorkbench. Полный прогон с одним штатным worker дал 200/200 за 76 секунд; исходники этих тестов, лимиты времени и конфигурация CI не менялись. Не следует считать параллельный прогон на этой машине стабильным.

AI review нашёл невозможность отправить описание предельной длины после добавления метаданных. Ошибка воспроизведена тестом и исправлена: форма сохраняет предел описания 1000 символов, канал принимает полное сообщение до серверного предела 20000. Проверка неверной привязки к врачу уточнена действительным кодом. AI review не заменяет независимое одобрение участника.

## Оставшиеся условия и недочёты

1. Публичный VPS ещё не обслуживает эту интеграцию. По фактической read-only проверке API отсутствует, Caddy не активен, PostgreSQL доступен только локально. Сервер не изменялся. Подготовленный в серверной ветке trusted-proxy вариант `ca0ee6d` необходимо совместить с этим изменением и проверить до HTTPS-публикации. Адрес `176.32.37.10` известен; публичный сертификат для текущего релиза не установлен и не проверен.
2. Согласно AGENTS.md, «Shared contracts, access control, clinical decision logic, migrations, deployment, and CI need review by the development lead»; если автор — глава разработки, нужен другой участник. Публикация и merge требуют соответствующего PR и актуального независимого review. В этом шаге push, PR, merge и deploy не выполнялись.
3. В debug-запуске Expo сообщает `Custom sound 'default' not found` при подготовке канала напоминаний. Это прежняя настройка `notificationPermissions.ts`, а не ошибка обмена сообщениями. Звук и доставка уведомлений требуют отдельной проверки; предупреждение не скрывалось правкой приложения.
4. У обращения нет постоянной очереди исходящих команд после закрытия формы. Повтор в открытой форме использует прежний commandId. Полная offline-синхронизация отложена.
5. Статусы доставки и прочтения врачебного сообщения автоматически не подтверждаются. Локальный план не становится назначением с сервера; дозы, опросники и игровой мир не синхронизируются.
6. Для эмулятора использован debug APK с Metro. Он не является готовой распространяемой HTTPS-сборкой. Временная нативная настройка dev-support находится только в `D:/sv5`, без переноса сгенерированного Android-проекта в исходники.

## Воспроизведение локального API

На Windows с .NET 10 и PostgreSQL tooling выполнить сборку API, затем `node scripts/verify-hackathon-access.mjs`. Пути tooling задаются `DOCTOR_DOTNET` и `DOCTOR_PG_BIN`. Скрипт создаёт только свою базу `syncli_hackathon` на порту 55453; секреты хранятся в игнорируемом `.cache/hackathon-access/local.json`. Он отказывается использовать занятый порт API 5096. Не запускать его одновременно с интерактивным API из этого же fixture.

Приватная серверная конфигурация включает `Hackathon:Enabled`, `PatientUserId`, `CodeHash`, `ExpiresAt`. Код хранится отдельным PBKDF2-хэшем; пароль служебной patient-учётной записи независим. Клиент получает только origin, без секретов. Отключение режима или истечение срока блокирует ранее выданную code-сессию.
