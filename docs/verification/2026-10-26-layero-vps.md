# Layero → VPS: реализация и проверка — 26.10.2026

> **Статус документа:** Историческое свидетельство: результаты и ограничения относятся к указанной ниже дате и версии. Они не являются текущим статусом всего продукта. [Текущее состояние](../status.md).

Задача [#44](https://github.com/souponin-d/psycho/issues/44), [PR #45](https://github.com/souponin-d/psycho/pull/45). Основной сайт остаётся `https://syncli-main.layero.app/`, статический doctor — `/doctor/`; Node-прокси предназначен только для `/api`. Финальный деплой Layero выполняет владелец.

## Реализовано

- `layero.json`: полный frontend dist и отдельный лёгкий Node 24 backend; код не требует npm-зависимостей в runtime.
- Прокси фиксированного HTTPS upstream: cookies/раздельные Set-Cookie, CSRF, методы/тела/коды, no-store, потоковые файлы, ограничение 2 МБ, JSON 502/504 и отсутствие автоматического повтора POST.
- Web: бюджет 45 секунд для первого запроса и сохранение неопределённого результата при оборванном JSON для повтора с тем же commandId.
- API: версия health и отдельный ограниченный допуск синтетической клиники в Production. Статусы клинических источников и правила подтверждения не изменялись.
- Updater: обязательные файлы/контрольные суммы, зашифрованная копия, проверка восстановления, атомарная ссылка релиза, сохранение env/ключей и откат.

## Фактическая поставка VPS

API установлен как `20261026-layero44-19e10c2`, исходный commit `19e10c2`. Linux API проверен по manifest перед передачей и на VPS. После переключения `/api/health` возвращает JSON:

```json
{
  "status": "ready",
  "storage": "postgresql",
  "release": "20261026-layero44-19e10c2",
  "contractVersion": "doctor-api-2026-10-26"
}
```

`/opt/syncli/current` указывает на новый релиз; `syncli-api`, Caddy и PostgreSQL активны. Существующий статический web и APK на VPS не заменялись; Android продолжает использовать прежний HTTPS origin. Режим ASP.NET остался Production, реквизиты/сертификаты/ключи сохранены, синтетические команды разрешены только выделенной клинике.

До переключения создана зашифрованная копия БД, api.env, PFX и ключей; расшифровка и восстановление в отдельную временную БД прошли, число карт/сообщений совпало. Зашифрованная копия скачана вне VPS в игнорируемый `.cache/layero44/backups/`, пароль сохранён отдельно в приватной папке.

На VPS дополнительно проведена репетиция сбоя: копия того же API с намеренно неуспешным health-check отклонена, updater вернул исходную ссылку и env. Проверены неизменность PFX и прежних ключей, ready исходного релиза, сохранность уже выданной пациентской cookie-сессии и переписки после перезапусков. Старый дообновлённый релиз `20261026-hackathon-v1` также сохранён для операционного отката.

## Что требует действий в Layero

В этом сеансе CLI не авторизован (`auth_required`). Поэтому запуск в runtime платформы, её сетевой egress, fullstack-маршрутизация и edge-cache не объявляются проверенными. Не выполнялись ручной production deploy или изменение настроек Layero. Актуальный публичный `/api/health` Layero до деплоя ещё возвращает HTML fallback.

После review/merge применить конфигурацию существующего проекта: корень репозитория, frontend полного dist, backend `deployment/layero`, node_web/Node 24, start `node server.mjs`, порт 3000, apiPrefix `/api`. Для preview нужен его точный origin в серверной переменной `SYNCLI_WEB_ORIGINS`. [Полная инструкция](../../deployment/layero/README.md).

После деплоя проверить именно публичный Layero-origin: JSON health/версию, вход/выход, сохранение после reload, две сессии без общего кэша, холодный старт и обмен с Android. Текущий live smoke проверяет локальный proxy → VPS и совместимость пациентского протокола; установленный APK/эмулятор в этом этапе повторно не проходился.

Сборщик предупреждает о крупных JS-чанках. При текущей серверной политике пользователи Node-прокси могут делить один IP-бюджет входа. Глобальное доверие к клиентским forwarded-заголовкам не включалось. Синтетическая проверка не означает допуск реальных медицинских данных.
