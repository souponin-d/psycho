В новые варианты не попадают исторические, исключённые, истёкшие и приостановленные статусы. Отдельно исключаются фармацевтические субстанции, явно обозначенные РУ `ФС-…` или формой «субстанция…». Неизвестный статус не считается действующим. Среди действующих учитываются даты окончания/аннулирования; пустая дата не превращается в отрицательный клинический факт.

Исключение для истечения даты: явный статус «Действует, на подтверждении государственной регистрации» сохраняется. Минздрав [относит его к применяемым действующим сведениям](https://minzdrav.gov.ru/special/documents/9892-opisanie-tehnicheskih-trebovaniy-k-vzaimodeystviyu-informatsionnoy-sistemy-posrednicheskoy-tsifrovoy-platformy-s-gosudarstvennoy-informatsionnoy-sistemoy-reestrom), отдельно от истёкших РУ. Окончание и аннулирование сохраняются как самостоятельные поля. Уже наступившее аннулирование исключает новую запись. При поиске и подтверждении срок проверяется на текущую дату UTC одинаково в браузере и API; обновление самого регистра не выполняется автоматически.

## Общий каталог и импорт

[Импортёр](../scripts/import-grls.mjs) читает ZIP и XLSX потоково существующим ExcelJS 4.4.0 workspace администратора. Новых зависимостей нет. Проверяются восемь статусов, единая дата имени/заголовка/подвала, столбцы, обязательные поля, календарные даты и число строк. Формулы не исполняются и отклоняются. Имена ZIP не используются как пути для распаковки. Смешанные префиксы SpreadsheetML в официальных rich-text ячейках приводятся к одному пространству имён в памяти, чтобы не потерять текст; исходные файлы не изменяются.

```powershell
node --max-old-space-size=4096 scripts/import-grls.mjs --archive=D:/Downloads/grls2026-10-23-1.zip
node scripts/import-grls.mjs --check
```

[Манифест](../apps/web-doctor/src/workspace/grls-manifest.json) хранит дату, версию, SHA-256 архива и каждого XLSX, числа строк/дублей/субстанций, SHA-256 сжатого и распакованного каталога. Идентификатор строки — SHA-256 всех её нормализованных регистрационных полей, включая исходный статус; это идентификатор снимка, а не вечный идентификатор препарата. Совпадение одного номера РУ не используется для склейки разных версий или форм.

Один `grls-catalog.json.gz` потребляется обоими контурами. Vite публикует его отдельным asset со ссылкой, учитывающей базовый путь, в самостоятельной и общей demo-сборке. ASP.NET копирует его в `Grls.json.gz` и проверяет SHA-256 при запуске. Браузер проверяет SHA-256 сжатого файла либо содержимого, если web-хост уже распаковал HTTP `Content-Encoding: gzip`. При ошибке загрузки доступны явная ошибка и повтор, а неполный файл не устанавливается как каталог. Ресурс около 7,78 МБ gzip / 78,53 МБ JSON, загружается и индексируется один раз при необходимости. Для первоначальной загрузки нужен web-хост; клинический API локальному режиму не нужен.

## Поиск, выбор и история

Поиск работает по МНН, торговому наименованию, РУ, формам выпуска, производственным сведениям и держателю. Регистр, е/ё и повторные пробелы нормализуются. Интерфейс показывает по 12 результатов с количеством и переходом; источник, статус, держатель и формы видны до/после выбора. Каталог содержит зарегистрированные варианты выпуска; конкретную дозу и режим вводит врач.

Защищённый врачебной сессией endpoint:

```text
GET /api/terminology/grls?q=парацетамол&page=1&pageSize=12
```

Ответ: `sourceVersion`, `snapshotDate`, `total`, `page`, `pageSize`, `items`. Запрос до 250 символов; страница от 1; размер 1–100. Возвращаются только актуальные записи по правилам выше. OpenAPI и клиент генерируются через `npm run contract:doctor`.

`PlanItem.medicine` — необязательный для исторических записей регистрационный снимок: система/версия, ID строки, РУ, название, МНН, формы, производственные сведения, держатель, даты и статус. Для нового лекарственного назначения требуется выбор актуальной записи; название плана соответствует выбранному препарату. Локальный домен и API проверяют точное сочетание полей. Подтверждение новой связанной записи повторно проверяет актуальность. Регистрационный статус не является статусом назначения.

Старые текстовые назначения сохраняются без угадывания РУ и без миграции IndexedDB/БД. Старый черновик без связи с ГРЛС допускает сохранение прежнего названия; новый препарат выбирается из каталога. Подтверждённый план нельзя переписать. Новая версия через `replacesId` сохраняет старый препарат и его снимок; меняется лишь статус прежнего назначения и документируется причина. При будущей смене справочника ранее сохранённый снимок удерживается только на исходной записи; автоматической замены сведений нет. Если связанный черновик больше не актуален, перед подтверждением нужен новый актуальный выбор.

Сравнение конфликтов показывает РУ, статус, версию, полную форму, производителя и держателя, даже если торговое название совпало. Подтверждение немедикаментозных задач и старых текстовых назначений не зависит от доступности ресурса ГРЛС.

Инструкции не импортируются, старое поле ссылки и прежние требования его проверки сохранены. Система не подбирает препарат, дозу или режим автоматически. Состав справочника не активирует клинические правила.

Обновление — повторный импорт, проверки и review всей связки каталога и приложения. Откат должен сохранять поддержку `medicine`; старая сборка, не знающая поля и нового ограничения выбора, не является безопасным откатом для новых записей. Автоматические обновления и внешнее развёртывание не выполнялись.
