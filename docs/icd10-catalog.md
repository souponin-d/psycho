# Полная российская МКБ-10

Снимок получен 26 октября 2026 года из [официальной ЕСНСИ](https://esnsi.gosuslugi.ru/classifiers/5697/data). Владелец справочника — Министерство здравоохранения Российской Федерации. OID: `1.2.643.5.1.13.13.11.1005`; идентификатор ЕСНСИ: `5697`. Публичный паспорт разрешает чтение `ANY` и выгрузку `downloadClassifier`. Отдельная лицензия в ответе паспорта не указана; собственная лицензия этому набору не приписывается.

## Версия и полнота

Используется ревизия **ЕСНСИ 444**, дата обновления в паспорте — `2026-10-25T03:08:39.142243Z`. Значение `esnsi-444` обозначает именно ревизию ЕСНСИ; оно не выдаётся за номер редакции исходного портала НСИ. Прямой портал НСИ во время исследования не отвечал. Клинические правила этим импортом не активируются.

Загружены все 16 страниц с закреплённым `version=444`: 15 страниц по 1 000 записей и последняя из 38. Итог `total=15038` сверялся на каждой странице; паспорт после загрузки оставался на ревизии 444. В снимке:

| Классы                                       |         22 |
| Блоки                                        |        274 |

Источник сохраняется целиком, включая идентификаторы, родительские связи, порядок, дополнительные признаки кодирования и даты изменения актуальности. Классы и блоки используются для поиска, но не выбираются как диагноз. Неактуальные записи отсутствуют среди новых вариантов. Заголовки официального справочника не исправляются вручную.

## Общий артефакт и обновление

[Каталог](../apps/web-doctor/src/workspace/icd10-ru.json) используется браузером и копируется в сборку ASP.NET Core как `Icd10Ru.json`. [Манифест](../apps/web-doctor/src/workspace/icd10-ru.manifest.json) содержит SHA-256 паспорта, каждой исходной страницы, нормализованного набора и готового файла. API проверяет SHA-256 файла при запуске и прекращает запуск при несовпадении.

Импорт воспроизводится [скриптом](../scripts/import-icd10.mjs):

```powershell
# Проверка включённого набора без сети
node scripts/import-icd10.mjs --check

# Получение текущей публичной ревизии и всех её страниц
node scripts/import-icd10.mjs --download

# Повторная нормализация сохранённых исходных страниц без сети
node scripts/import-icd10.mjs --cache=.cache/icd10-source-research
```

Скрипт проверяет итог, порядок страниц, уникальность кодов/ID, родительские ссылки и циклы, наличие всех классов и допустимые статусы. Если ревизия во время загрузки изменилась, импорт прерывается. Новый снимок проверяется и проходит review вместе с потребителями; приложение не заменяет справочник из внешней сети во время работы врача. Для сохранения исторических выборов при будущей смене версии нужно добавить прежний снимок в реестр сохранённых версий до выпуска обновления.

## Поиск и сохранение

Локальный поиск работает по включённому набору без обращения к API. Учитываются регистр, `е/ё`, лишние пробелы; код можно ввести как `u 07 . 1`. Доступны фрагменты кода, слова названия, названия классов и блоков, обозначение блока `A00-A09` и точный класс `Класс I`. Поиск `I` остаётся поиском фрагмента кода; для точного класса используется слово «Класс». Точное совпадение кода стоит первым. Интерфейс показывает по 12 результатов с переходом между страницами и общим количеством.

Защищённый врачебной сессией endpoint:

```text
GET /api/terminology/icd10?q=U07.1&page=1&pageSize=25
```

Ответ: `sourceVersion`, `total`, `page`, `pageSize`, `items`. Номер страницы начинается с 1; размер — 1–100; запрос — до 250 символов. Пустой запрос открывает весь актуальный набор. Пустая страница за пределами выдачи не меняет общий итог. OpenAPI и клиент создаются через `npm run contract:doctor`.

Профиль пациента, диагнозы приёма и диагноз эпизода сохраняют `{system, sourceOid, sourceVersion, code, title}`. Локальные команды и API проверяют точное сочетание этих полей, а также полномочие на подтверждение диагноза. Сервер не доверяет присланному названию. Ошибка не изменяет запись или её ревизию. Уже действующие подтверждения, аудит и неизменяемые снимки приёма сохраняются.

## Совместимость

[Прежние 17 учебных записей](../apps/web-doctor/src/workspace/icd10-legacy.json) заморожены только для чтения и сохранения на той записи, где они уже находились. Новая карта или новый приём не могут получить этот старый выбор. В интерфейсе видна историческая версия; для замены врач удаляет старую запись и выбирает актуальный код. Старое название не заменяется автоматически даже при совпадении кода.

У эпизода добавлено необязательное поле `diagnosisCode`; прежнее поле `diagnosis` сохраняется для совместимости. При выборе кода оно формируется из кода и официального названия и проверяется на совпадение. Старый свободный текст отображается без угадывания кода и может быть сохранён неизменным; новый свободный диагноз не принимается. Сброса IndexedDB, SQL-миграции или удаления истории не требуется. После появления новых версионированных записей откатывать приложение на старую сборку с 17 кодами нельзя: она не распознаёт новые значения; для отката нужен совместимый справочник и валидатор.
