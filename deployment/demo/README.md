# Хакатонный стенд на VPS

Синтетический контур опубликован 26.10.2026 по прямому поручению владельца: Android → HTTPS VPS → PostgreSQL → кабинет врача → ответ Android. Это отдельный хакатонный стенд, без утверждения о медицинском production-профиле. Официальный кейс и клинические правила не изменяются.

- Кабинет: <https://176.32.37.10/doctor/>.
- API health: <https://176.32.37.10/api/health>.
- Самостоятельный Android APK 0.4.2: <https://176.32.37.10/downloads/Syncli-0.4.2.apk>.
- [Отчёт и изображения](../../docs/verification/2026-10-26-vps-hackathon.md).

## Устройство установленного стенда

`syncli-api.service` запускает Linux ASP.NET Core 10 в Production от `syncli`, только на `127.0.0.1:5080`. PostgreSQL 17 остаётся на loopback:5432; отдельная БД/роль — `syncli_hackathon`. Caddy 2.11.7 принимает 80/443, перенаправляет HTTP на HTTPS и сохраняет `/api` при proxy. API доверяет только ближайшему `127.0.0.1`, обрабатывает forwarded headers до редиректов и не доверяет forwarded Host.

Действующие файлы находятся в `/opt/syncli/releases/20261026-hackathon-v1/api` и `/srv/syncli/releases/20261026-hackathon-v1`; ссылки `current` указывают на них. Настройки — `/etc/syncli/api.env` (root:syncli, 0640), сертификат шифрования ключей — `/etc/syncli/dataprotection.pfx` (0640), ключи Data Protection — `/var/lib/syncli/keys` (syncli, 0700). Из интернета не доступны порты API, БД и Caddy admin.

`Caddyfile.ip` использует публичный IP-сертификат Let's Encrypt и профиль `shortlived`. Caddy автоматически обновляет сертификат; службу и её постоянное хранилище нельзя удалять между обновлениями. `default_sni` обслуживает клиентов, которые не отправляют SNI при соединении с IP. Сертификат защиты Data Protection — отдельный PFX, а не публичный TLS-сертификат.

Код имеет отдельный PBKDF2-хэш и не является обычным паролем patient-учётной записи. Срок выданного тестового кода — до **2 ноября 2026, 16:13 МСК**; выключение/просрочка режима закрывает code-сессии. Сам код, пароли и backup-secret не включаются в репозиторий, APK или инструкции. Выданы владельцу отдельно.

## Первичная установка и проверка

`install-hackathon.py STAGE PRIVATE_JSON RELEASE_ID` предназначен для первичной установки на выделенный VPS от root. `STAGE` содержит framework-dependent Linux API, полную `dist/` как `web/`, unit и `Caddyfile.ip`. Приватный JSON передаётся отдельно по SSH. Скрипт не обновляет существующую инсталляцию: отказывается перезаписывать релиз, PFX, env или `current`; БД не удаляет и не очищает. Он сохраняет прежний Caddyfile, валидирует новый и явно перечитывает активный Caddy после запуска служб.

После установки синтетическая карта создаётся через HTTPS API: `scripts/verify-vps-hackathon.py PRIVATE_JSON --seed`. Затем на VPS `provision-hackathon-patient.py PRIVATE_JSON` связывает выделенную учётную запись с этой картой штатной provision-командой. `scripts/verify-vps-hackathon.py PRIVATE_JSON` проверяет HTTPS, роли, сессии, CSRF, повтор команды и ответ врача. Приватные JSON не публикуются вместе со статикой.

На текущем компьютере прямой маршрут к IP через VPN недоступен. Проверка использовала ограниченный CONNECT-туннель только к `176.32.37.10:443` через Wi-Fi; он не расшифровывает TLS и не заменяет VPS локальным API. У эмулятора задан сетевой proxy `10.0.2.2:8898`. Это настройка тестовой среды, а не содержимое APK. На телефоне с обычным доступом в интернет специальный proxy не нужен. При переносе эмулятора в другую сеть старый proxy следует убрать.

## Резервирование и восстановление

После обмена сообщениями создана зашифрованная копия БД, `api.env`, PFX и ключей Data Protection. Копия находится на VPS в `/root/syncli-backups/` и вне VPS — на компьютере владельца в игнорируемом `.cache/vps-release/backups/`. Пароль резервной копии хранится отдельно в приватной конфигурации владельца. Шифрование архива — AES-256-CBC с PBKDF2, 600000 итераций; SHA-256 копии сверен после передачи. Это прототип резервирования, без автоматического расписания.

Архив расшифрован с проверкой целостности исходных байтов, dump восстановлен в новую временную БД. Число карт/сообщений совпало; созданная проверочная БД удалена. Рабочая БД не пересоздавалась. Для реального восстановления сначала расшифровать архив в закрытый каталог, восстановить dump в отдельную БД, восстановить выделенную роль из приватной конфигурации и проверить доступ. Только затем переключать API. PFX и каталог ключей восстанавливаются вместе с env; секреты нельзя помещать в аргументы команд или журналы.

## Обновление и откат

Новый код публикуется в новый каталог релиза. Сначала проверяются контракт, сборка, HTTPS/proxy и сохранность данных; затем меняется только ссылка приложения и перезапускается `syncli-api`. Действующие PFX, ключи и БД сохраняются. Для изменения Caddy обязательны `caddy validate` и `systemctl reload caddy`.

На этом первом релизе предыдущего приложения нет. Аварийный откат — остановить `syncli-api` и Caddy, при необходимости восстановить сохранённый `/etc/syncli/backups/Caddyfile-20261026-hackathon-v1`; SSH и PostgreSQL не отключать, БД/ключи не удалять. Merge и дальнейшая поставка исходников идут через PR; AI review не заменяет независимое человеческое одобрение.
