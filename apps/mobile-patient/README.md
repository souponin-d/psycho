## Хакатонный канал 0.4.2

Публичный синтетический стенд: [кабинет врача](https://176.32.37.10/doctor/). [Проверка на VPS](../../docs/verification/2026-10-26-vps-hackathon.md) подтверждает обмен из release APK без Metro.

React Native + Expo SDK 55, TypeScript, Expo Router. Только синтетические сведения. Демо работает локально; хранение, история, экспорт и напоминания остаются на устройстве. Серверный режим использует существующее приглашение и канал обращений/ответов врача. Локальный чат-навигатор и игровой мир не отправляются в карту врача.

Первый вход: выданный серверный код в существующем поле либо «Войти в демо-режиме». Тринадцать шагов с сохранением прогресса знакомят с планом, спутником, темой, личной целью, напоминаниями и картой. Повторное подключение не сбрасывает записи. После холодного запуска серверный режим требует код снова; секрет не сохраняется в профиле.

«Мой путь» — вертикальная календарная карта с выполненными, пропущенными и будущими днями. Для зачёта нужны все приёмы, обязательный самоотчёт и назначенные на дату опросы. Граница — строго 00:00 местного времени. Исправления старой истории не восстанавливают стрик и не меняют закрытые награды. Пять выполненных дней семидневной главы дают недельную награду независимо от непрерывности серии. Предметы остаются после пауз.

Два окружения, варианты света/растений, 20 предметов, 12 достижений и редактор расстановки. Два спутника с 12 состояниями, ходьбой, реакциями на предметы и независимыми гардеробами. Исходные цвета и лица маскотов сохраняются без перекрашивания. Доступны три предмета одежды, три аксессуара и вариант без аксессуара. Игровое оформление можно отключить, сохранив обычный план.

В свежем сценарии заполнены восемь прошлых дней, сегодня открыт, серия равна 1, сад уже доступен. На сегодня назначен полный PHQ-9; первоначальный GAD-7 пройден в синтетической истории. Пациент видит только факт прохождения. Ответы и баллы не входят в графики, сводку, JSON/PDF. Паспорта форм: [источники и ограничения](../../docs/specifications/doctor-web/2026-10-24-patient-questionnaire-passports.md). Клиническая активация для реальных пациентов требует отдельной валидации.

Модель содержит датированное уточнение плана: прежние обязательные поля самоотчёта сохраняются для прошлых дат, сегодняшние определяются новой версией. Назначения пациент не редактирует. Время напоминаний меняется отдельно от схемы.

## Обновление интерфейса 0.4.1

- Текущий выбор тем и смайлик карты ощущений сохранены; заголовок настроек — «Настройки».
- В карточке приёма видны препарат и указанная в плане дозировка; недостающее значение не выдумывается. Даты мира показаны по-русски.
- В «Рядом» компактная шапка и быстрые действия; очистка доступна через меню. Сохранение не называется доставкой врачу.
- Сохранены графики, в том числе сон: дата выбирается касанием, значение доступно текстом и символом помимо цвета.
- Окраски удалены из обучения/мастерской; старые поля профиля остаются совместимыми. При смене одежды/реакции готовый кадр остаётся видимым до подготовки следующего.
- Только две оговорённые надписи деморежима остаются на шаге подключения: «Войти в демо-режиме» и «Сейчас подключается учебный план на синтетических данных…». Исходные факты старого профиля не переписываются ради отображения.

[Хакатонный контракт](../../docs/contracts/hackathon-access.md): `EXPO_PUBLIC_PATIENT_API_ORIGIN` задаёт HTTPS origin без секретов. `EXPO_PUBLIC_PATIENT_LOCAL_HTTP=1` разрешён только для локальных проверок loopback/эмулятора. Provider подключает `patientChannel` после кода; получает сообщения и обновляет их каждые 10 секунд в активном приложении. Сообщения сохраняются в очереди для конкретного сервера, пациента и пользователя; после сбоя отправка повторяется при активном подключении тем же идентификатором. На экране отображается ожидание отправки. После перезапуска повтор начинается после входа по коду. Успех отправки означает подтверждение сервера, а не прочтение врачом. Синхронизация остальных данных описана в [плане готовности](../../docs/contracts/mobile-integration-readiness.md).

## Запуск и сборка

Из корня с Node.js 24:

```sh
npm ci --ignore-scripts
npm run dev:mobile
npm run check:mobile
npm run prebuild:android --workspace @psycho/mobile-patient
```

Для локального Android release нужны JDK 17 и Android SDK, указанные в `JAVA_HOME`/`ANDROID_HOME`. Из `apps/mobile-patient/android`:

```powershell
.\gradlew.bat :app:assembleRelease '-PreactNativeArchitectures=arm64-v8a,x86_64'
```

Результат: `android/app/build/outputs/apk/release/app-release.apk`. Перед Gradle обязательно выполнить prebuild: сгенерированный `android/` может содержать старый versionCode. Пакет `ru.syncli.patient.demo`, версия 0.4.4, versionCode 8. Сохраняйте прежний локальный ключ подписи, чтобы обновлять приложение без удаления данных. Итоговый проверенный файл, SHA256 и ограничения приёмки перечисляются в отчёте поставки.

## Напоминания Android

Следующее описание относится к деморежиму. В серверном режиме напоминания и быстрые действия уведомлений пока отключены, чтобы локальные учебные отметки не выдавались за серверные.

Нужны разрешение уведомлений и, для точного времени, специальный доступ к будильникам. Статус и переход к настройкам видны в приложении. Уведомление о приёме позволяет отметить приём без открытия интерфейса или отложить сигнал на 15 минут. Действие связано с датой, версией назначения и слотом; повтор не создаёт второй факт.

Планируются ближайшие 28 дней с ограничением до 60 сигналов; расписание обновляется при открытии/возврате и смене настроек. Это не обещание бесконечной фоновой работы. После системного force-stop Android блокирует сигналы до самостоятельного запуска приложения. Произвольные ограничения батареи производителя требуют проверки на конкретном телефоне. Физический телефон не подключён: эмуляторная проверка не выдаётся за неё.

## Данные и редактирование

Текущие факты, черновики, закрытые дни и награды сохраняются транзакционно в SQLite. Старые настройки/история из AsyncStorage мигрируют один раз и сохраняются в архиве без выдуманных координат. Периоды 7/30 дней, календарь, графики, редактирование/удаление и журнал исправлений доступны в истории. JSON/PDF создаются внутри приложения; системный выбор папки и отправка запускаются только отдельной кнопкой. ## Проверка

`npm run check:mobile` запускает TypeScript, ESLint и поведенческие Node-тесты отдельно от web/.NET/БД. Перед поставкой также выполняется `npm run check`. Эмуляторные сценарии находятся в `scripts/verify-*.mjs`, по умолчанию используют собственный `emulator-5570` и пишут доказательства в `artifacts/`. Они проверяют реальные касания и системную доставку; часть сценариев меняет синтетические данные и потому запускается осознанно.

[Карта и редактор](../../docs/verification/2026-10-25-mobile-world-editor.md), [спутники и запись движения](../../docs/verification/2026-10-25-mobile-companions.md), [онбординг и фоновые уведомления](../../docs/verification/2026-10-25-mobile-onboarding-notifications.md). Уменьшение движения учитывает и системную настройку, и переключатель пользователя; это нужно проверять отдельно от активной анимации.
